## 목적

v0(`index.html` 1.2k 라인, 라운드 1 규칙)를 **v2 규칙의 1막→2막 1사이클**로 교체해, 제안서 §7 kill-criterion 을 **지인 2~4인 + 셀프 플레이로 판정할 수 있는 한 덩어리**를 만든다. 슈퍼센트 과제 제출물(마감 2026-09-07), 판정일 2026-09-02 저녁.

재미 가설은 하나 — **"손으로 익힌 초식이 자동화되는 순간이 보상이다"**. 프로토타입에서 "자동화"는 **제자가 내 무공을 대신 구사하는 것**이고, 그 자격은 내 손이 그 무공을 완벽히 깨달았다(12성)는 증표다. 성립 조건 넷:

- **(a) 입력 = 선택 + 실행** — 선택은 **후보가 갈라지는 분기 키**에서, 그 뒤 꼬리가 실행. 같은 비급의 초식은 같은 첫 키로 시작해 도중에 갈라지므로 비급 1권인 프로토타입에서는 2번째 키가 선택 축, 다권(M2+)이면 첫 키부터 비급 단위로 갈라진다(스케일에 따라 분기점이 이동할 뿐 규칙은 같다). **지금 보이는 내 속성 색 = 현재 후보 리스트 최상단 초식의 속성** — 키를 칠수록 색이 답하고, 수동 입력은 도중에 갈래(속성)를 바꿀 수 있지만 원터치는 고정. **입력 장치는 PC·모바일 동일 4방향 키**(PC 방향키/WASD, 모바일 하단 4방향 버튼).
- **(b) 숙련 = 손의 권한, 성 = 깨달음의 증표 (두 축)** — 초식 단위 **숙련도** 0~100%: 힌트(0~30%) → 후보만(30~99%) → **원터치(100%)**. 무공 단위 **성(成)** 1~12: 위력이 오르고 10성이 통상의 최고, 11·12성은 파해를 완파한 자만 — **12성 = 전수·분해 자격**. 시퀀스 입력은 유저 전용(사부 자동응수 없음).
- **(c) 순차 해금 → 12성 → 전수(복사) → 파견** — 하위 초식 100% 가 다음 초식의 학습 조건. 12성 무공은 제자에게 **복사**(사부 보유 유지, 제자는 1성부터). 제자 = 성·레벨이 있는 자동 용병 — **실행은 항상 성공**하고 유저는 어느 제자를 세울지·(원하면) 어느 초식을 쓰게 할지 **지시**만 한다. 2막의 해방 = **첫 파견을 손 놓고 보는 것**.
- **(d) 자명성** — 튜토리얼 없이 첫 초식 발동 ≤ 60초. "예고 색 → 내 후보 색 대조" 와 자동완성식 후보 축소가 설명 없이 읽힌다는 가설.

**판정 형태** (n=2~4 에서 성립하는 것만): kill 4항은 **개인별 pass/fail 의 과반**. (a) 첫 발동 60초 · (c) 설문은 **지인 전용**, (b) 힌트 소멸 후 성공률 · (d) 완주 300초는 지인 + 셀프, **봇은 페이스 회귀 참고치**. 비율 임계는 개인 세션 안 기준. 판정은 기본 설정(접근성 옵션 off). **(c) 문항 = "내가 익힌 무공을 제자가 쓰는 걸 보는 게 좋았다"**(구조의 정서 — 폴백 연출 품질과 분리; 연출 만족도는 보조 문항). **인식률 선행 게이트**: 셀프·봇에서 `ignore_rate` > 15% 면 버튼 히트·배치를 먼저 튜닝한 뒤 (b) 를 읽는다.

**통합 1개로 만드는 이유**: 6 서브시스템이 한 상태기계의 부품(여행자의 단어장 M1 작업 7 — 분할이 통합 결함을 마지막에 노출) + 단일 파일. 대가는 ⑥ 의 서브시스템별 로그 + build 순차 이슈로 상쇄.

## 내용

**MVP 스코프**: 비급 1권 「유운검법」 4식 · 도전자 A(사부 대련, 재도전 3차) + 도전자 B(파견) · 실전 슬롯 3 · 제자 1명(레벨 1 = 무공 슬롯 1) · 6단 판정 · 수련 시뮬 · 로그 내보내기. **범위 밖**: 사부 자동응수·커버(개념 없음) / 스와이프 입력(폐기) / 오프라인 타임스탬프 정산·HMAC 세이브(M2) / 제자 2명+·레벨업·고용(M2) / **제자 능력치 아이템**(사용 시 새 무공을 1성이 아닌 N성부터 — M2+) / 재화 소비처(M2+: 장비 무기·의복 / 소모품 내공 증진·체력 회복 / 비급 구매 / 도장 운영 / 제자 고용·레벨) / 원정 모드(비가시 임무 → 복귀 보고 전투 횟수·전리품 — S1, 오프라인 축과 결합) / 상대 쪽 진행형 색·허초·변초(S2) / 무공 분해·창작·진법(S3) / 광고·IAP / 아트·사운드 실파일(M3 — 코드 렌더·Web Audio 합성 폴백) / 왼손 모드(십자 좌우 배치, M2).

**1사이클 순서와 시간 예산** (목표 300초 — **성공률 70% 가정**, 4식은 사이클 뒤):

### ① 후보 필터 시퀀스 입력부 (유저 전용)

- **비급 첫 키 공유·2번째 키 분기**: 유운검법 4식은 모두 `↓` 로 시작(초식 식별자 = 고유 시퀀스, prefix-free; 속성은 초식별 값으로 한 비급 안 혼재). 다권(M2+)이면 비급마다 첫 키가 달라 첫 키부터 갈라진다.
- 장착 = 실전 슬롯 3(장착 조건 숙련 ≥ 30%). 키마다 `candidates = 버퍼를 접두어로 갖는 장착 초식`, **정렬 = 숙련 높은 순 → 동률 슬롯 순**(결정적). **후보 0 이 되는 키 = 오입력 무시**(버퍼·후보 불변). 리셋 버튼(십자 옆 고정 / `Space`·`Esc`)만. **발동 = 후보 1 ∧ 버퍼 == 시퀀스** → `fire{styleId, r}` → ②.
- **진행형 후보 색**: 최상단 초식의 속성이 "지금 내 색"으로 크게 표시(리스트 헤더 + 버퍼 색). 최상단이 바뀌면 색이 바뀐다 — 상대 색(예고 확정 1색)과 대조하며 좁힌다. 후보 1개면 즉시 확정, 원터치는 색 고정. 상대 쪽 진행형 색은 S2 변초의 표현.
- **입력 장치 통일 — 4방향 키**: PC 방향키/WASD, 모바일 **화면 하단 십자 4버튼**(엄지 존, 히트 56px+, 후보 아이콘은 버튼 위쪽 별도 영역) → 같은 `onDirection(dir)`. 스와이프 없음. **입력 피드백 2종**: 수락(버퍼 진행 + 버튼 눌림) / 무시(후보 0 — 셰이크 200ms + 회색 화살표 튕김 + 둔탁음). 같은 창 무시 3회 → 리셋 하이라이트.
- **읽기·판단은 예고, 실행은 창**: 예고 **1.0s**, 창 `T = 2.6 + 0.5 × (len − 3)`(3/4/5 = 2.6/3.1/3.6s — v0 같은-길이 승계 + 긴 초식 여유, D3 는 줄이는 방향). 봇 스펙으로 5길이 2.55s + 분기 판단 0.5s < 3.6s. 접근성 ×1.3 옵션(기본 off).
- 후보 표시: 아이콘(속성 3색 테두리 + 형태 ▲●■). 0~30%: 후보 아래 잔여 화살표 힌트 / 30~99%: 아이콘만 / 100%: 아이콘 탭 = 원터치. 후보 1 도달 시 중앙 확대 + 이름. 버퍼 한 줄(v0 `#seq`).
- `assertPrefixFree(styles[])`: 로드·장착 시 assert(⑤ 와 동일 함수).

### ② 6단 공방 판정부 (데이터 드리븐 + 헤드리스 하네스)

- 한 수: 예고 1.0s(상대 초식 아이콘 + 속성 색 확정 + 조짐) → 창 `T` → 교차 판정 → 연출 0.5s. 대련 = HP 소진 또는 12수.
- 판정표(판정 설계 §2-2): 파해 → 완파(100% + 상대 빈틈) / 속성 승 → 우세(60/20) / 동속성 → 상쇄(내공차 × k) / 속성 패 → 열세(20/60) / 상대 절초의 파해 대상을 냄 → 역파(0/100 + 나 빈틈) / 미완주 → 피격. 쾌>강>정>쾌, 파해 우선.
- 수식: `D` 10/14/20 · **내공 `N = 1 + 0.05 × 성`**(판정 설계 §3 의 숙련 기반 `N` 대체; 10성 1.5, 12성 1.6. 내공 소모 자원은 M2) · 선기 `1 + 0.3r` · 상쇄 `max(0, ΔN) × D × k`(0.5) · 빈틈 1수.
- 전부 `BALANCE` JSON, 순수 함수 `judge()` 로 6단 × 빈틈 × 선기 × 성 전 조합 하네스 회귀. 판정표 변경 = 하네스 기대값 같은 커밋.
- 정보 노출: 상대 속성 색 항상 / 내 진행형 색 항상 / 파해는 구결 텍스트만 / 절초 1개는 도전자 예고 / 잔여 힌트 0~30% 만. 우세 후보 강조(펄스) 없음. **삼각 한 줄**(`쾌 > 강 > 정 > 쾌`, 예고 속성 항 강조) = **새 초식 해금마다 첫 5수**(`triangleHintExchanges` 해금 이벤트마다 리셋 — 프로토 2식·3식 2회, 최대 10수).

### ③ 숙련(초식) · 성(무공) · 순차 해금 · 실전 슬롯 · 전수

- **숙련도**(초식 0~100%): 수련 모드 **3회** 성공 → 30%(졸업·장착 가능) / 실전 성공(판정 ≥ 상쇄) 누적 `threshold`(**유운보 4 · 2식 4 · 3식 5 · 4식 5**) → 100% = 원터치. 슬롯에서 빼도 보존.
- **순차 해금**: N식 숙련 100% → N+1식 학습 가능(도장 「배우기」). 재화 게이트 없음.
- **성**(무공 1~12): 그 무공 초식의 성공 발동 누적 **2회당 +1**(1→10). **11성 = 완파 1회, 12성 = 다른 초식으로 완파 1회 더**. 성 → 내공 `N`. 성 상승 = 무공 카드 「N성」 배지 + 짧은 연출.
- **실전 슬롯 3**: 4식이 열리면 4 > 3 이라 장착 선택 발생(도장에서만 교체).
- **전수 = 복사**: 조건 = 무공 12성 ∧ 제자 무공 슬롯 여유. 사부는 무공·숙련·성 보유. **제자 무공은 1성부터**(M2+ 아이템으로 시작 성 상향). **전수 장면 = 구조적 순간**: 「유운검법 12성 — 완벽히 깨달음」 배지 → 사부 카드·제자 카드가 나란히, 같은 무공 아이콘이 제자 쪽에 **켜진다** → (파견 첫 수에서 제자가 그 초식을 친다). 시연 1회·스팅어·1.0s 연출은 덧칠(폴백 합성음). 12성 무공 분해는 표시만(S3).
- 단계 라벨: 문하생 → 고수(첫 전수). 사부·일대종사는 M2+.

### ④ 제자 = 자동 용병 · 파견 (관전 기본 + 선택적 지시)

- 제자 1명(레벨 1 · 무공 슬롯 1). 제자 무공 성 1~10(사용 누적 상승, 12성은 유저만). **제자 실행은 항상 성공**(실패·성공률 없음) — 성은 위력 `N` 만. 실행 시점 = 창의 **60%**.
- **파견 = 관전이 기본**: 도전자 B 와 제자가 대련, 제자는 매 수 **자동 선택**(상대 속성에 우세인 초식 중 성 높은 것; 없으면 상쇄; **상대 절초의 파해 대상 초식은 제외**(역파 회피)). 유저 화면은 보는 화면 — 알림·재촉·타이머 없음.
- **지시 = 원할 때만**: 예고 중 제자 초식 아이콘이 작게 떠 있고, 탭하면 그 수만 지정(파해 노림 → 완파·연환). 탭 여유 = 예고 1.0s + 창의 60% 시점까지 ≈ 2.5s. 파해로 끝낼 수 있는 수(도전자 예고에서 공개된 정보 기준)는 아이콘 **반짝임 1회**로 유도(강제 아님).
- 제자 패배 = 도전자 도주(손실 없음). 파견 결과 화면: 승패 · 성 변화 · 재화. 원정(비가시·보고형)은 S1.

### ⑤ 데이터 — 유운검법 4식 · 도전자 A/B · 도전자 예고

- 초식 테이블: id · 무공 · 이름 · 한자 · 속성 · 시퀀스(첫 키 `↓`, 2번째 키 분기) · `D` · 파해 대상 · 구결. 4식 = 유운보 쾌 3(`↓→↑`) · 2식 강 3(`↓←→`) · 3식 정 4(`↓↑→←`) · 4식 쾌 5(`↓↓→←↑`) — 속성 혼재라 분기 키 = 속성 선택.
- 무공 테이블: 유운검법 {초식 4, 성 1~12, 전수 조건}. 제자 테이블: {레벨 1, 무공 슬롯 1, 성 map}.
- 도전자 A(사부, 재도전 3차: α → α·β → α·β·γ, 절초 없음; α 파해 = 유운보, β = 2식, γ = 3식) / 도전자 B(파견: α·γ + 절초 δ 공개, δ 파해 = 4식 — 사이클엔 없어 제자가 상쇄·열세로 버팀 → 4식 동기). **B 밸런스 게이트**: 1성 제자(N 1.05) 무지시 자동으로 B 를 이기는지 하네스 시뮬(12수·HP) — 못 이기면 B 의 `N`·HP 를 낮춘다(kill d 는 승패 무관 완주 판정이지만 첫 파견 패배는 해방 정서를 죽인다).
- **도전자 예고 화면**(파견 전): 유파명 + 절초 δ 아이콘·속성 → 제자 세팅 확인. 파해 1:1 무결성 + `assertPrefixFree` 를 데이터 커밋마다 하네스. 이름·구결 [[무공 초식 조사]] §2-5 수작업 4+4.

### ⑥ 검증 로그 · 재화 · 봇 v2 · 파라미터 표

- 로그(세션 버퍼 → 「로그 내보내기」 JSON): `key{dir, accepted, candidates_n, top_attr, device: keyboard|button}` · `ignore{dir}` · `reset` · `narrow{styleId}` · `fire{styleId, len, oneTap, r}` · `timeout` · `verdict{grade, dmg_out, dmg_in, state, who}` · `mastery{styleId, from, to}` · `rank{style_set, from, to}` · `unlock{styleId}` · `slot{action, styleId}` · `transmit{style_set}` · `dispatch{challenger}` · `select{styleId, byUser}`(지시/자동) · `coins{delta, reason}` · `cycle{phase}` · `session{tester_role: self|friend|bot, device}`. 전부 `t_ms`.
- **개인별 pass/fail**: (a) friend `first_fire_t ≤ 60s` / (b) self+friend 힌트 소멸 후 `fire/(fire+timeout) ≥ 0.5` / (c) friend 설문 "내가 익힌 무공을 제자가 쓰는 걸 보는 게 좋았다" ≥ 4 / (d) self+friend `cycle_done_t ≤ 300s`(= `dispatch` 종료). **선행 게이트**: `ignore_rate` > 15%(셀프·봇) → 입력 튜닝 후 (b) 판독. 보조: `first_transmit_t` · `select.byUser` 비율 · `oneTap` 비율 · `ignore_rate`(device 별) · `tail_ms` · `top_attr` 전환 횟수 · 연출 만족도 문항.
- **재화**: 획득·표시만(수련 시뮬 `simEfficiency` 0.1 × 3600 + 대련·파견 보상). 소비처 M2+(장비·소모품·비급·도장 운영·제자 고용·원정 전리품).
- 봇 v2: 반응 0.45~0.65 · 키당 0.26~0.38 · 15% 미입력으로 1사이클 자동(파견 무지시) → `balance-log.md`. `tester_role: bot`.
- `BALANCE`: 예고 1.0 / `T` 2.6 + 0.5·(len−3) / 접근성 1.3(off) / `D` 10·14·20 / 내공 0.05·성 / 우세·열세 60·20 / k 0.5 / 선기 0.3 / 빈틈 −40% / 수 상한 12 / 수련 졸업 3 / `threshold` 4·4·5·5 / 성 2회당 1 / 11·12성 완파 1·2 / 제자 시작 성 1 / 제자 실행 0.60 / `triangleHintExchanges` 5(해금마다) / `simEfficiency` 0.1 / 버튼 히트 56px.

## 예상되는 플레이와 기대하는 재미

- **0~60초 (긴장)**: 비급을 열면 유운보(청). 도전자 예고에 적(강) → 장착이 유운보뿐이라 첫 키에 후보 1, 내 색 청 확정 → 힌트 화살표 따라 하단 버튼(모바일)/방향키(PC) 세 번. "색 확인 → 따라 치기" 두 걸음. α 를 유운보로 파하면 「완파!」 + 빈틈 → 연환.
- **1~3분 (숙달·선택)**: 30% 에 힌트가 사라지고 꼬리는 손이 친다. 유운보 100% 원터치 → 선기 +30%. 2식(강)이 들어오는 순간 `↓` 뒤 **후보 둘, 내 색 = 최상단(유운보·청)**, 삼각 한 줄이 5수 동안 뜬다 — 청 예고에 청으로 가면 상쇄, `←` 로 강에 가면 열세… 한 번 맞고 **색을 보게 된다**. 3식(정)이 오면 삼각 줄이 다시 5수 뜨고 `↑` 로 갈라지며 색이 녹으로 바뀐다 — "입력할수록 화면이 답한다". 완파 두 번에 **12성**.
- **3.5분 (전수)**: 12성 배지 → 사부 카드 옆 제자 카드에 유운검법이 **켜진다**. 무공은 내게 남고 제자에게도 생겼다.
- **4~5분 (해방·파견)**: 도전자 B 예고에 절초 δ(정). 제자를 보내고 **손을 놓는다** — 제자가 색을 보고 알아서 친다. 파해로 끝낼 수 있는 수에 아이콘이 한 번 반짝이면, 원하면 탭해서 "그걸로 끝내" 라고 지시한다. 이기면 「고수」. "4식을 배우면 δ 도 완파" 가 다음 동기.
- **실수 경험**: 오입력 무벌(셰이크), 갈래 오진입도 유효 응수(색이 바뀌는 걸 보고 알아챔). 스와이프가 없어 "안 읽혔다" 는 없다.
- **검증 로그 → 개인별 pass/fail**: (a)(c) friend / (b)(d) self+friend — 4항 각각 과반 fail 이면 kill(제안서 §7 → B안 「퍼즐용사」 피벗). `ignore_rate` 선행 게이트. 보조 지표는 D3 튜닝 입력.

## 예상되는 문제점과 해결 방안

1. **새 초식이 들어와 후보가 둘·셋이 되는 첫 선택에서 멈춘다**.
   → 해결: 순차 해금이 후보를 1→2→3 으로 키워 그때까지 예고 색을 10수 넘게 봤고, **해금마다 첫 5수** 삼각 한 줄. 진행형 색이 "지금 가는 갈래의 색"을 보여줘 예고 색과 대조. 우세 후보 직접 강조 없음(학습 보호).

2. **오입력이 "안 눌린다"로 읽힌다** — 후보 0 이 되는 키를 눌렀을 때.
   → 해결: 수락(버튼 눌림 + 버퍼 진행) / 무시(셰이크 + 회색 화살표 튕김 + 둔탁음) 2종 피드백 + 같은 창 무시 3회 → 리셋 하이라이트. 모바일은 하단 십자 버튼이라 인식 실패 자체가 없음. `ignore_rate` 가 15% 를 넘으면 버튼 히트·간격을 먼저 튜닝.

3. **잘못 든 갈래로 좁혀졌는데 모른 채 완주**.
   → 해결: 갈래를 잘못 들면 **내 색이 바뀐다** + 후보 1 도달 시 확대·이름 / 장착 조건 ≥ 30% 라 잔여 시퀀스를 안다 / 완주하면 유효한 응수. 리셋은 포기 버튼.

4. **4·5길이 창이 빡빡해 리듬게임으로 읽힌다**.
   → 해결: 판단은 예고 1.0s, 창은 실행 전용 + 긴 초식 계수 0.5(넉넉히 시작해 D3 에서 줄임). 접근성 ×1.3 옵션.

5. **파견에서 "지시할 이유가 안 보인다"** — 관전이 기본이라 지시 기능이 있는지도 모르고 지나간다.
   → 해결: 파해로 끝낼 수 있는 수(도전자 예고 공개 정보 기준)에 제자 초식 아이콘 **반짝임 1회** — 지시하면 완파·연환이 되는 것을 한 번 보여주는 유도, 강제 아님. `select.byUser` 로 개입도 측정. 개입 없이도 제자가 이기는 것이 첫 파견의 본체.

6. **12성까지의 반복이 지루하다**.
   → 해결: 성은 2회마다 배지 연출, 11·12성은 **완파** 라는 질적 조건. 순차 해금이 초식을 하나씩 열어 후보·색 변화가 계속 새로움. 성공 필요 22회로 압축(안건 1). 커브는 D3·M2 파라미터.

7. **전수가 밋밋하다** — 연출 리소스가 폴백뿐.
   → 해결: 전수의 실체를 연출이 아닌 **구조**로: 12성 배지 → 사부·제자 카드에 같은 무공이 켜짐 → 파견 첫 수에서 제자가 그 초식을 친다. 코드 렌더로 성립. kill (c) 문항도 구조의 정서를 묻는다.

8. **6단 판정 결과가 한 수 안에 읽히지 않는다**.
   → 해결: 등급 = 색 + 한 글자 즉시 중앙 / 피해 = HP 바 애니메이션 / 빈틈 = 다음 예고 자리 「빈틈!」 배너. 접근성 색 + 글자 + 형태.
