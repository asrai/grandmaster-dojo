# 프로토타입 v2 통합 PRD — Spec

**안건**: 프로토타입 v2 통합 PRD (일대종사 / 프로토타입-v2)
**생성**: /gamedev-spec v0.11 (통합 spec 구조 룰 v0.19), 2026-09-01
**소스**: [[brief_프로토타입_v2_통합_PRD_05]] (debate 미경유 직행 — cycle 05, `debate_skipped: true`)

---

## 개요

v0(`index.html` 1.2k 라인, 라운드 1 규칙)를 **v2 규칙의 1막→2막 1사이클**로 교체해, 제안서 §7 kill-criterion 을 지인 2~4인 + 셀프 플레이로 판정할 수 있는 한 덩어리를 만든다 (슈퍼센트 과제 제출물, 마감 2026-09-07, 판정일 2026-09-02 저녁).

재미 가설은 하나 — **"손으로 익힌 초식이 자동화되는 순간이 보상이다"**. 자동화 = 제자가 내 무공을 대신 구사하는 것, 자격 = 내 손이 그 무공을 완벽히 깨달았다(12성)는 증표. 성립 조건 4: (a) 입력 = 선택(이기는 색 매칭) + 실행 / (b) 숙련 = 손의 권한 · 성 = 깨달음의 증표 (독립 2축) / (c) 순차 해금 → 12성 → 전수(복사) → 파견 / (d) 자명성 (튜토리얼 없이 첫 발동 ≤ 60초).

**M1 통합 spec 1개** (dotfiles #1532) — 6 서브시스템이 한 상태기계의 부품 + 단일 파일이라 분할하지 않는다. 대가는 `### 통합 로그 스키마`(서브시스템별 이벤트 분리 식별) + `/gamedev-build` 순차 이슈 1~3개 (병렬 금지) 로 상쇄한다.

**아키텍처 원칙**: `BALANCE` 단일 객체 + 상태기계 1개(도장 / 사부 대련 / 전수 / 파견) + 초식·무공·도전자·제자 테이블 JSON + 로그 버퍼. 판정·숙련·성·전수·제자 선택은 순수 함수 (헤드리스 하네스가 DOM 없이 실행). ①~⑥ 경계 = build 순차 이슈 경계.

## 구현 스펙

> M1 통합 안건 — `## 구현 스펙` 을 brief § 내용의 서브시스템 ①~⑥ 과 1:1 sub-section 으로 구조화 (순서 = 의존 순서). EARS REQ 표는 각 서브시스템 안에 두고 번호대를 끊는다 (①=101~ / ②=201~ / ③=301~ / ④=401~ / ⑤=501~ / ⑥=601~). REQ ID 는 spec 문서 내 유일. `(depends:)` 는 데이터/구조 의존만.

### ① 후보 필터 시퀀스 입력부 (유저 전용)

### 요구사항 (EARS)

- **REQ-101** *(Ubiquitous)*: The system shall 4방향 입력을 단일 경로 `onDirection(dir)` 로 통일한다 — PC 방향키/WASD, 모바일 화면 하단 십자 4버튼 (엄지 존, 히트 56px+, 후보 아이콘은 버튼 위쪽 별도 영역). 스와이프 없음.
- **REQ-102** *(Event-driven)*: When 방향 입력이 수락되면, the system shall `candidates = 버퍼를 접두어로 갖는 장착 초식` 으로 갱신하고, 정렬 = 숙련 높은 순 → 동률 슬롯 순 (결정적) 을 유지한다. *(depends: REQ-501, REQ-305)*
- **REQ-103** *(Unwanted)*: If 입력 키로 후보가 0 이 되면, then the system shall 그 키를 오입력으로 **무시** 하고 (버퍼·후보 불변) 무시 피드백 (버튼 셰이크 200ms + 회색 화살표 튕김 + 둔탁음) 을 출력한다. *(depends: REQ-102)*
- **REQ-104** *(Unwanted)*: If 같은 응수 창 안에서 무시가 3회 누적되면, then the system shall 리셋 버튼을 하이라이트한다. *(depends: REQ-103)*
- **REQ-105** *(Event-driven)*: When 리셋 (십자 옆 고정 버튼 / `Space` / `Esc`) 입력 시, the system shall 버퍼를 비우고 후보를 장착 초식 전체로 복원한다.
- **REQ-106** *(Event-driven)*: When 후보 1 ∧ 버퍼 == 시퀀스 가 되면, the system shall `fire{styleId, len, oneTap, r}` 를 발동해 판정부(②)에 전달한다. *(depends: REQ-102)*
- **REQ-107** *(Ubiquitous)*: The system shall **진행형 후보 색** 을 표시한다 — 후보 리스트 최상단 초식의 속성을 "지금 내 색"으로 크게 (리스트 헤더 + 버퍼 색), 최상단이 바뀌면 즉시 갱신. 후보 1개면 즉시 확정 색, 원터치는 색 고정. *(depends: REQ-102)*
- **REQ-108** *(State-driven)*: While 실전 응수 창에서 미완성(<100%) 초식이 후보일 때, the system shall 잔여 화살표를 키마다 `hintDelay`(0.5s) 뒤에 점등한다 (**딜레이드 힌트**). 수련 모드는 즉시(0). *(depends: REQ-301)*
- **REQ-109** *(Event-driven)*: When 숙련 100% 초식의 후보 아이콘을 탭하면, the system shall 즉시 발동 (**원터치**, `oneTap: true`, 잔여 시퀀스 생략, r = 탭 시점 잔여 비율) 한다. *(depends: REQ-301)*
- **REQ-110** *(Event-driven)*: When 후보가 1개에 도달하면, the system shall 그 초식을 중앙 확대 + 이름 표시한다.
- **REQ-111** *(Event-driven)*: When 입력이 수락되면, the system shall 수락 피드백 (버퍼 진행 + 버튼 눌림) 을 출력한다.
- **REQ-112** *(Ubiquitous)*: The system shall 후보 아이콘을 속성 3색 테두리 (쾌 청 / 강 적 / 정 녹) + 형태 (▲●■) 로 중복 표현한다.
- **REQ-113** *(Ubiquitous)*: The system shall `assertPrefixFree(styles[])` 를 로드·장착 시 assert 한다 (⑤ REQ-505 와 동일 함수). *(depends: REQ-501)*

### ② 6단 공방 판정부 (데이터 드리븐 + 헤드리스 하네스)

### 요구사항 (EARS)

- **REQ-201** *(Ubiquitous)*: The system shall 한 수를 다음 타임라인으로 진행한다 — **상대 예고** 1.0s (상대 초식 아이콘 + 속성 색 확정 + 이기는 색 + 조짐; 항상 도전자 쪽 개념) → 응수 창 `T = 2.6 + 0.5 × (len − 3)` (3/4/5길이 = 2.6/3.1/3.6s) → 교차 판정 → 연출 0.5s. 대련 = HP 소진 또는 12수 (12수 도달 시 잔여 HP 비교 승패).
- **REQ-202** *(Event-driven)*: When 양측 초식이 확정되면 (또는 미완주), the system shall 6단 판정을 적용한다 — 파해 → **완파** / 속성 승 → **우세** / 동속성 → **상쇄** / 속성 패 → **열세** / 상대 절초의 파해 대상을 냄 → **역파** / 창 안 미완주 → **피격**. 속성 삼각 = 쾌>강>정>쾌, **파해가 삼각보다 우선**. (판정표 SoT: [[13. 일대종사/1. 구상/공방 판정 설계|공방 판정 설계]] §2) *(depends: REQ-106, REQ-501)*
- **REQ-203** *(Ubiquitous)*: The system shall 피해를 수식으로 산출한다 — 기본 피해 `D` = 길이별 10/14/20 · 내공 `N = 1 + 0.05 × 성` (10성 1.5, 12성 1.6 — 판정 설계 §3 의 숙련 기반 N 을 brief 05 가 대체) · 선기 `1 + 0.3r` · 우세/열세 60/20 · 상쇄 `max(0, ΔN) × D × k` (k=0.5) · 역파/피격 = 상대 피해 100%. *(depends: REQ-304)*
- **REQ-204** *(State-driven)*: While 빈틈 상태일 때, the system shall — **상대 빈틈** (완파 후 1수): 상대 예고 없음(방어 불능) + 내 아무 초식 완주 = 완파 취급 (연환) / **나 빈틈** (역파 후 1수): 응수 창 −40%. 1수 지속, 중첩 없음. *(depends: REQ-202)*
- **REQ-205** *(Ubiquitous)*: The system shall 판정 로직 전체를 `BALANCE` JSON + 순수 함수 `judge()` 로 데이터 드리븐화하고, 헤드리스 하네스가 6단 × 빈틈 × 선기 × 성 전 조합을 DOM 없이 회귀한다. 판정표 변경 = 하네스 기대값 같은 커밋. *(depends: REQ-202)*
- **REQ-206** *(Ubiquitous)*: The system shall 상대 예고에 **「이기는 색」** (상대 속성에 우세인 1색, 예: `→ ●청`) 을 상시 병기한다 (`winColorHintExchanges = ∞` 프로토 상시). 우세 *후보 아이콘* 강조 (펄스) 없음 · 삼각 규칙표 한 줄 없음 — 속성은 안내하되 어느 초식·시퀀스인지는 유저가 찾아 친다. *(depends: REQ-201)*
- **REQ-207** *(Ubiquitous)*: The system shall 정보 노출을 다음으로 한정한다 — 상대 속성 색 항상 + 이기는 색 병기 / 내 진행형 후보 색 항상 / 파해는 비급 구결 텍스트만 / 절초 1개는 도전자 예고에서 공개 / 힌트는 딜레이드 (REQ-108).
- **REQ-208** *(Unwanted)*: If 응수 창 안에 완주하지 못하면 (timeout), then the system shall 피격 판정을 적용하고 `timeout{styleTop, buffer_len}` 을 로깅한다. *(depends: REQ-202)*
- **REQ-209** *(Unwanted)*: If 유저가 대련에서 패배하면 (HP 소진 또는 12수 판정패), then the system shall 결과 화면에서 **「재도전」/「도장으로」** 를 제시하고, 재도전 시 손실 없이 (숙련·성·재화 보존 — 적립은 발동 시점 반영이라 보존) 같은 차수를 HP 리셋으로 재시작한다. (제자 패배 = 도전자 도주 무손실과 동형 — 역질문 확정 2026-09-01) *(depends: REQ-201)*
- **REQ-210** *(Optional)*: Where 접근성 옵션 (기본 off) 이 켜지면, the system shall 응수 창을 ×1.3 한다. kill 판정은 기본 설정 기준.
- **REQ-211** *(Event-driven)*: When 판정 결과가 나오면, the system shall 등급 = 색 + 한 글자를 중앙에 즉시 / 피해 = HP 바 애니메이션 / 빈틈 = 다음 예고 자리 「빈틈!」 배너로 표시한다 (색 + 글자 + 형태 중복 표현). *(depends: REQ-202)*

### ③ 숙련(초식) · 성(무공) · 순차 해금 · 실전 슬롯 · 전수

### 요구사항 (EARS)

- **REQ-301** *(Ubiquitous)*: The system shall 초식 단위 **숙련도** 0~100% 를 관리한다 — 수련 모드 3회 성공 → 30% (졸업 = 장착 가능) / 실전 **유효 성공** 누적 `threshold` (유운보 4 · 2식 4 · 3식 5 · 4식 5) → 100% = 원터치 권한. 슬롯에서 빼도 보존.
- **REQ-302** *(Ubiquitous)*: The system shall **유효 성공** 을 "판정 ≥ 상쇄인 발동" 으로 판정하고, 이를 숙련 threshold 와 성 포인트의 공통 적립 단위로 쓴다. 수련 모드 성공 (창 내 완주 — 판정 없음) 도 유효 성공으로 취급한다. **완주율** (kill b — 손 입력 fire, 판정 무관, 원터치 제외) 과는 별개 축 — 갈래 오진입 완주는 (b) 성공이지만 적립 아님. *(depends: REQ-202)*
- **REQ-303** *(Event-driven)*: When N식 숙련이 100% 에 도달하면, the system shall N+1식 학습을 도장 「배우기」 에서 가능하게 한다 (**순차 해금**, 재화 게이트 없음). *(depends: REQ-301)*
- **REQ-304** *(Ubiquitous)*: The system shall 무공 단위 **성(成)** 1~12 를 관리한다 — **성 포인트** `rankPts` = 그 무공 초식의 유효 성공 발동당 **초식 차수** (1식 1 · 2식 2 · 3식 3 · 4식 4, 수련 포함) / 2~10성 = `rankStep` 3pt/성 (10성 27pt) / 11성 +6 (2배) · 12성 +12 (4배) = 총 45pt. 최소 경로 (수련 3+실전 4)×1 + (3+4)×2 + (3+5)×3 = 7+14+24 = 45pt → 3식 실전 5회째 12성. 성 → 위력 `N` (REQ-203). 11성 승리 N회 · 12성 파훼 N회 조건은 M2 (소급). *(depends: REQ-302)*
- **REQ-305** *(Ubiquitous)*: The system shall **실전 슬롯 3** 을 제공한다 — 장착 조건 숙련 ≥ 30%, 교체는 도장에서만. 4식 해금 시 4 > 3 장착 선택 발생.
- **REQ-306** *(Event-driven)*: When 성이 오르면, the system shall 무공 카드 「N성」 배지 + 짧은 연출을 출력한다. 12성 도달 시 「완벽히 깨달음」 배지. *(depends: REQ-304)*
- **REQ-307** *(Event-driven)*: When 전수 조건 (무공 12성 ∧ 제자 무공 슬롯 여유) 이 충족되어 유저가 전수를 실행하면, the system shall 무공을 제자에게 **복사** 한다 — 사부는 무공·숙련·성 보유 유지, 제자는 그 시점까지 사부가 학습한 초식들로 1성부터. **전수 장면 = 구조적 순간**: 12성 배지 → 사부 카드·제자 카드가 나란히, 같은 무공 아이콘이 제자 쪽에 켜진다 (연출 폴백 = 코드 렌더 + 합성음). *(depends: REQ-304, REQ-401)*
- **REQ-308** *(Ubiquitous)*: The system shall **수련 모드** 를 제공한다 — 상대·판정 없이 응수 창 `T` (실전과 동일 수식) 안에 시퀀스 완주 = 성공, 힌트는 즉시 (hintDelay 0). 실패 (창 초과) 는 무벌 재시도. *(depends: REQ-301)*
- **REQ-309** *(Event-driven)*: When 첫 전수가 완료되면, the system shall 단계 라벨을 문하생 → **고수** 로 올린다 (사부·일대종사는 M2+). *(depends: REQ-307)*

### ④ 제자 = 자동 용병 · 파견 (관전 기본 + 선택적 지시)

### 요구사항 (EARS)

- **REQ-401** *(Ubiquitous)*: The system shall 제자 1명 (레벨 1 = 무공 슬롯 1) 을 관리한다 — 제자 무공 성 1~10 (같은 성 포인트 룰, 상한 10 — 12성은 유저만), 시작 성 1. *(depends: REQ-502)*
- **REQ-402** *(Ubiquitous)*: The system shall 제자 실행을 **항상 성공** 시킨다 (실패·성공률 없음 — `p` 개념 소멸). 실행 시점 = 응수 창의 60%. 성은 위력 `N` 에만 반영. *(depends: REQ-203)*
- **REQ-403** *(Event-driven)*: When 파견 중 상대 예고가 뜨고 유저 지시가 없으면, the system shall 제자 초식을 **자동 선택** 한다 — 상대 속성에 우세인 초식 중 성 높은 것 → 없으면 상쇄 → **상대 절초의 파해 대상 초식은 제외** (역파 회피). *(depends: REQ-202, REQ-401)*
- **REQ-404** *(Event-driven)*: When 유저가 상대 예고 중 떠 있는 제자 초식 아이콘을 탭하면, the system shall 그 수만 해당 초식으로 **지시** 한다 (탭 여유 = 상대 예고 1.0s + 창의 60% 시점까지 ≈ 2.5s). *(depends: REQ-403)*
- **REQ-405** *(Event-driven)*: When 그 수의 상대 예고에 공개된 상대 초식의 파해를 제자가 보유하면, the system shall 해당 제자 초식 아이콘을 **반짝임 1회** 로 유도한다 (강제 아님 — 지시하면 완파·연환을 한 번 보여주는 장치). *(depends: REQ-404, REQ-501)*
- **REQ-406** *(Unwanted)*: If 제자가 패배하면, then the system shall 도전자 도주 처리한다 (손실 없음). 파견 종료 시 결과 화면: 승패 · 성 변화 · 재화. *(depends: REQ-403)*
- **REQ-407** *(Ubiquitous)*: The system shall 파견 화면을 관전 기본으로 유지한다 — 알림·재촉·타이머 없음. *(depends: REQ-403)*

### ⑤ 데이터 — 유운검법 4식 · 도전자 A/B · 도전자 예고

### 요구사항 (EARS)

- **REQ-501** *(Ubiquitous)*: The system shall 초식 테이블을 JSON 으로 정의한다 — 컬럼: id · 무공 · 이름 · 한자 · 속성 · 시퀀스 · `D` · 파해 대상 · 구결. 유운검법 4식 (첫 키 `↓` 공유, 2번째 키 분기, prefix-free): 유운보 쾌 3 (`↓→↑`) · 2식 강 3 (`↓←→`) · 3식 정 4 (`↓↑→←`) · 4식 쾌 5 (`↓↓→←↑`). 이름·구결 = [[13. 일대종사/1. 구상/무공 초식 조사|무공 초식 조사]] §2-5 수작업 4+4.
- **REQ-502** *(Ubiquitous)*: The system shall 무공·제자 테이블을 정의한다 — 유운검법 {초식 4, 성 1~12, 전수 조건 12성} / 제자 {레벨 1, 무공 슬롯 1, 성 map}. *(depends: REQ-501)*
- **REQ-503** *(Ubiquitous)*: The system shall 도전자 데이터를 정의한다 — **A** (사부 대련, 재도전 3차: 1차 α → 2차 α·β → 3차 α·β·γ, 절초 없음; 파해: α=유운보 · β=2식 · γ=3식) / **B** (파견: α·γ + 절초 δ 공개, δ 파해 = 4식 — 사이클엔 없어 제자는 우세로 깎되 완파 불가 → 4식 동기). 적 초식 속성·길이 시드: α 강 3 (D10) · β 정 4 (D14) · γ 쾌 4 (D14) · δ 정 5 (D20). *(depends: REQ-501)*
- **REQ-504** *(Event-driven)*: When 파견 진입 전, the system shall **도전자 예고 화면** 을 표시한다 — 유파명 + 절초 δ 아이콘·속성 → 제자 세팅 확인. *(depends: REQ-503)*
- **REQ-505** *(Ubiquitous)*: The system shall 파해 1:1 무결성 + `assertPrefixFree` 를 데이터 커밋마다 하네스로 검증한다. *(depends: REQ-501, REQ-503)*
- **REQ-506** *(Ubiquitous)*: The system shall **B 밸런스 게이트** 를 하네스 시뮬로 검증한다 — 1성 제자 (N 1.05) 무지시 자동으로 B 를 이기는지 (12수·HP); 못 이기면 B 의 `N`·HP 를 낮춘다 (첫 파견 패배는 해방 정서를 죽인다). *(depends: REQ-403, REQ-503)*

### ⑥ 검증 로그 · 재화 · 봇 v2 · 파라미터 표

### 요구사항 (EARS)

- **REQ-601** *(Ubiquitous)*: The system shall 세션 로그 버퍼에 통합 로그 스키마 (아래 표) 의 전 이벤트를 `t_ms` 와 함께 기록한다. *(depends: REQ-201, REQ-106, REQ-304)*
- **REQ-602** *(Event-driven)*: When 유저가 「로그 내보내기」 를 누르면, the system shall 세션 버퍼를 JSON 으로 내보낸다. *(depends: REQ-601)*
- **REQ-603** *(Ubiquitous)*: The system shall 로그만으로 kill 4항의 **개인별 pass/fail** 산출이 가능하게 한다 — (a) friend `first_fire_t ≤ 60s` / (b) self+friend 실전 창 중 원터치 창 제외 `fire(oneTap=false) / (fire(oneTap=false) + timeout) ≥ 0.5` / (c) friend 설문 "내가 익힌 무공을 제자가 쓰는 걸 보는 게 좋았다" ≥ 4 (로그 외 입력) / (d) self+friend `cycle_done_t ≤ 300s` (= `dispatch` 종료). **선행 게이트**: `ignore_rate` > 15% (셀프·봇) → 입력 튜닝 후 (b) 판독. 보조: `first_transmit_t` · `select.byUser` 비율 · `oneTap` 비율 · `ignore_rate` (device 별) · `tail_ms` · `top_attr` 전환 횟수. *(depends: REQ-601)*
- **REQ-604** *(Ubiquitous)*: The system shall 재화를 획득·표시만 한다 — 수련 시뮬 (`simEfficiency` 0.1 × 3600) + 대련·파견 보상 (시드: 대련 승리 30 · 파견 승리 50). 소비처 없음 (M2+). *(depends: REQ-601)*
- **REQ-605** *(Ubiquitous)*: The system shall 사람 속도 **봇 v2** 를 제공한다 — 반응 0.45~0.65s · 키당 0.26~0.38s · 15% 미입력으로 1사이클 자동 (파견 무지시) → `balance-log.md` 회차 기록. `session{tester_role: bot}`. 봇 수치는 페이스 회귀 참고치 (kill 판정 입력 아님). *(depends: REQ-601)*
- **REQ-606** *(Ubiquitous)*: The system shall 밸런스 파라미터 전부를 `BALANCE` 단일 객체에 둔다 (아래 파라미터 표 = 시드값, D3 데이터 게이트로 튜닝). *(depends: REQ-205)*

### 상태 머신 / 핵심 로직

- 상태기계 1개: **도장** (배우기 / 수련 / 장착 / 전수 / 대련·파견 진입) ↔ **사부 대련** (A 1·2·3차 — 승리 시 다음 차수 해금, 재진입은 도장에서 수동) ↔ **전수** (12성 시) ↔ **파견** (B). `cycle{phase}` 로그가 구간 경계.
- 순수 함수 (헤드리스 하네스 대상): `judge()` (6단 판정 + 피해) · 숙련/성 적립 · 전수 조건 · 제자 자동 선택 · prefix-free/파해 무결성 assert.
- 1사이클 목표 300초 (유효 성공률 70% 가정 시 ≈235s, 50% 시 ≈290s) — 구간 예산은 brief 05 § 내용 표를 따른다 (0~35s 수련 → 35~90s A 1차 → 90~145s A 2차 → 145~205s A 3차·12성 → 205~225s 전수 → 225~290s 파견).

### UI / UX 명세

- 화면 골격: 도장 (사부 카드 · 제자 카드 · 무공 카드 「N성」 배지 · 배우기/수련/장착) / 대련 (상대 예고 + 이기는 색 · HP 바 2 · 후보 리스트 + 진행형 색 헤더 · 버퍼 한 줄 (v0 `#seq` 승계) · 하단 십자 4버튼 (모바일) · 리셋 버튼) / 전수 장면 (REQ-307) / 도전자 예고 화면 (REQ-504) / 파견 관전 (REQ-403~407) / 결과 화면 (REQ-209, REQ-406).
- 아트·사운드 실파일 없음 (M3) — **코드 렌더 (도형·텍스트) + Web Audio 합성 폴백** 으로 전 화면 성립. 속성 3색 + 형태 ▲●■ 중복 표현 (색각 접근성).

### 기술 의존성

- HTML5 vanilla JS, 단일 파일 `index.html`, 의존성 0 (엔진 ADR: [[13. 일대종사/1. 구상/엔진 결정 (HTML5 vs Unity WebGL)|엔진 결정]]).
- 빌드 단계 없음 — 로컬 서버 (`python3 -m http.server`) + 브라우저. 헤드리스 하네스는 DOM 없이 순수 함수만 import (Node 실행).
- v0 (라운드 1 규칙) 를 **교체** — v0 규칙 회귀 유지 의무 없음.

## 수용 기준 (Acceptance Criteria)

### 1. 데이터/빌드

- [ ] `index.html` 로컬 서버 로드 시 콘솔 런타임 에러 0, `node --check` 급 구문 통과

### 2. 동작 (input → expected)

- [ ] 케이스 1 *(REQ-106, 108, 201)*: 첫 진입 → 유운보 수련 3회 → A 1차에서 힌트 따라 `↓→↑` 완주 → `fire` + 판정 + `first_fire_t` 기록 (예산 ≤ 60s 경로 성립)
- [ ] 케이스 2 *(REQ-102, 107, 206)*: A 2차, `↓` 입력 → 후보 2 (유운보·2식), 내 색 = 최상단 청 → 예고 이기는 색 ●적 → `←` 로 갈래 전환 → 내 색 적 갱신
- [ ] 케이스 3 *(REQ-103, 104)*: 후보 0 되는 키 입력 → 버퍼·후보 불변 + 셰이크·둔탁음, 같은 창 3회 → 리셋 하이라이트
- [ ] 케이스 4 *(REQ-108)*: 실전 미완성 초식 — 화살표가 키마다 0.5s 뒤 점등; 3키 힌트 의존 완주 가능 (≈2.55s ≤ 2.6s), 4키는 창 초과 (하네스: 힌트 페이스 len×0.85s 시뮬)
- [ ] 케이스 5 *(REQ-202~204)*: 하네스 — 6단 × 빈틈 × 선기 × 성 전 조합의 등급·피해 정수·상태 전이 기대값 일치
- [ ] 케이스 6 *(REQ-302, 304)*: 최소 경로 재현 시뮬 — 수련 9 + 실전 13 유효 성공 → 유운보/2식 100% · 3식 실전 5회째 45pt = 12성
- [ ] 케이스 7 *(REQ-307, 309)*: 12성 → 전수 실행 → 제자 카드에 유운검법 켜짐 (1성, 초식 1~3) + 사부 보유 유지 + 라벨 고수
- [ ] 케이스 8 *(REQ-403, 405, 506)*: 파견 무지시 — 제자 자동 선택 (우세→상쇄→역파 회피) 으로 B 승리 (하네스 시뮬 green); α 수에 반짝임 1회 발생
- [ ] 케이스 9 *(REQ-404)*: 반짝임 수에 아이콘 탭 → 그 수만 지시 초식로 실행 → `select{byUser: true}`
- [ ] 케이스 10 *(REQ-209)*: 유저 HP 소진 → 결과 화면 → 재도전 → 같은 차수 HP 리셋, 숙련·성·재화 보존
- [ ] 케이스 11 *(REQ-601~603)*: 1사이클 후 로그 내보내기 → JSON 만으로 (a)(b)(d) 산식 + `ignore_rate` 계산 가능 (필드 결손 0)
