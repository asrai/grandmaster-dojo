# UI · 그래픽 스타일 레퍼런스 조사 (인접 장르 호평작)

- 작성: 2026-09-01 (KST)
- 목적: #24 레이아웃 고정(393×852 스테이지) 이후 착수할 **"게임 화면다운 UI + 배경 아트 + 캐릭터 애니메이션"** 작업의 설계 입력
- 성격: 조사 문서 (결정 문서 아님). 여기서 좁힌 후보는 `/gamedev-ui` 또는 spec 단계에서 확정한다.
- 제약 전제: HTML5 vanilla JS · zero dependency · no build step · 논리 해상도 393×852 세로 고정 · 에셋은 AI 생성 파이프라인

## 0. 조사 범위와 선정 기준

우리 게임은 한 장르에 깔끔히 안 들어간다. **아이들 아케이드(하이브리드 캐주얼) × 무협 × 시퀀스 입력 액션**의 교집합이라, 단일 장르 벤치마크로는 답이 안 나온다. 그래서 5개 축으로 나눠 각 축의 호평작을 조사했다.

| 축 | 왜 이 축인가 | 조사 대상 |
|---|---|---|
| A. 실루엣 액션 | 저예산으로 "액션 가독성"을 확보한 검증된 해법 | One Finger Death Punch 2, Shadow Fight 2, Punch Club |
| B. 무협 아트 | 세계관 톤 (수묵·강호) | Wandering Sword, Phantom Blade Zero, Where Winds Meet |
| C. 하이브리드 캐주얼 아이들 UI | 우리 상위 장르의 UI 문법 | Capybara Go, Legend of Mushroom, Eatventure, Pick Me Up Idle |
| D. 무협 방치형 (국내/중화권) | 같은 테마 + 같은 진행 구조 | 무제(정통무협방치형RPG), 화산파 키우기, 낭만강호, 활협전 |

## 1. 축 A — 실루엣 액션: 저비용으로 가독성을 사는 법

### One Finger Death Punch 2
- 입력이 **좌/우 두 버튼뿐**인 초고속 액션. 스틱피겨 실루엣으로 캐릭터를 그린다.
- 핵심은 **"캐릭터는 실루엣, 배경은 디테일"** 이라는 역할 분리다. 플레이어가 매 프레임 판독해야 하는 정보(적이 어느 쪽에서, 얼마나 가까이)는 흑백 대비로 즉시 읽히고, 분위기 담당인 배경은 마음껏 화려해도 된다.
- 디테일 부족은 **사망 애니메이션의 다양성**으로 메운다. 즉 "정지 화면의 퀄리티"가 아니라 "움직임의 퀄리티"에 예산을 몰아준 사례.

> **우리에게 시사점**: 대련 화면에서 판독 대상은 상대의 초식 텔레그래프와 6단 판정 결과다. 캐릭터를 실루엣으로 두면 (a) AI 에셋 생성 난이도가 급감하고 (b) 판정 이펙트가 캐릭터 디테일과 색이 겹쳐 묻히는 사고를 구조적으로 막는다.

### Shadow Fight 2
- 3D 모델을 **검은 실루엣으로 렌더**하고 배경만 디테일하게 그리는 2.5D. "모든 동작이 명확하면서 스타일리시하다"는 평가가 일관된다.
- 실루엣이 **아트 예산 절감 수단이 아니라 아이덴티티**가 된 케이스. 우리가 실루엣을 고를 경우 참고해야 할 태도 — "덜 그린 것"이 아니라 "그렇게 정한 것"으로 보여야 한다.

### Punch Club (픽셀 아트)
- 실무 규칙 하나가 유용하다: **모든 오브젝트에 아웃라인을 두르되, 아웃라인은 그 오브젝트의 가장 어두운 부분보다 더 어둡게**. 작은 오브젝트도 예외 없이.
- 이건 픽셀 아트 전용 규칙이 아니라 **어떤 스타일에서도 통하는 형태 분리 규칙**이다. CSS `filter: drop-shadow()` 나 `outline` 으로 zero-dep 구현이 가능하다.

## 2. 축 B — 무협 아트: 톤의 방향

- **Wandering Sword**: 픽셀 아트 캐릭터를 3D 배경 위에 얹은 하이브리드. 옥토패스 트래블러 계보. → "레이어별로 표현 밀도를 다르게 가져가도 성립한다"는 또 하나의 증거.
- **Phantom Blade Zero**: 중화권 AAA 파도 중 가장 시각적으로 구별되는 작품으로 꼽히며, **수묵(ink-wash) 미학 + 현대 그래픽** 조합이 그 이유로 지목된다.
- **Where Winds Meet**: 고증 텍스처의 밀도로 평가받는다 (우리 예산 밖 — 방향성 참고만).

> **시사점**: 무협 톤의 시각적 지분은 **먹 번짐 · 붓질 · 여백 · 붉은 낙관(도장) · 세로쓰기 한자** 같은 소수의 강한 기호가 대부분 가져간다. 캐릭터를 정교하게 그려서 무협을 표현할 필요가 없다. 이건 실루엣 노선과 완벽하게 양립한다 — 오히려 궁합이 좋다(먹 실루엣).

## 3. 축 C — 하이브리드 캐주얼 아이들 UI 문법

Supersonic(하이브리드 캐주얼 퍼블리셔)의 8원칙 + 하이퍼캐주얼 UI 가이드에서 우리에게 유효한 항목만 추림.

1. **장르와 시각 언어를 일치시켜라** — 팔레트·폰트·아이콘·버튼 모양까지 전부 세계관의 일부. (현재 우리 UI는 다크 대시보드 톤 = 세계관 미표현)
2. **UI 는 목적 없는 요소를 두지 않는다** — 작은 글씨, 누르기 어려운 버튼, 바쁜 화면이 금기.
3. **기능은 점진 공개** — 처음엔 단순, 숙련도에 따라 열린다. (우리 "숙련도 = 자동화 권한" 과 정확히 같은 구조 → UI 도 같은 곡선을 따라야 한다)
4. **플랫폼 최적화** — 모바일은 **엄지 도달 범위**에 조작을 배치.
5. **진행 바 · 일일 목표는 코어 루프가 굳은 뒤에 붙인다** (지금은 아직 아님)
6. **접근성은 처음부터** — 색 이외의 시각 단서 병행, 텍스트 크기 조절. (우리 `#a11y` 체크박스가 이미 이 축에 있다)
7. **모든 입력에 즉각적·식별 가능한 시청각 응답** — 버튼 색 변화, 점수 튀어오름, 햅틱.
8. **A/B 테스트** — 과제 범위 밖.

호평작 아트 방향(Capybara Go · Legend of Mushroom): **둥근 형태 · 표정이 살아있는 얼굴 · 따뜻하고 접근하기 쉬운 색**. 아이들 장르의 "부담 없음"을 아트가 먼저 약속한다.

> **긴장 관계 주의**: 아이들 장르의 아트 관습(코지·둥글둥글)과 무협의 아트 관습(먹·긴장·여백)은 서로 당긴다. 둘 다 하려다 어정쩡해지는 게 이 조합의 실패 패턴이다. **한쪽을 톤의 주인으로 정하고 다른 쪽은 액센트로 쓰는 결정이 필요하다** (§ 6 후보안 참조).

## 4. 축 D — 무협 방치형 (동일 테마 + 동일 구조)

- **무제: 정통무협방치형RPG** — 직관적 UI 덕에 세밀한 조작이 수월하다는 평. 방치형에서 UI 는 "정보 밀도를 감당 가능하게 만드는 장치"로 평가받는다.
- **화산파 키우기 (2024-11)** — 웹소설 IP 기반 무협 방치형. 국내 시장에서 무협 + 키우기 조합의 수요가 검증된 사례.
- **활협전** — "무협지를 읽는 듯한 경험"이 호평의 핵심. 텍스트·선택지의 문체가 아트만큼 세계관을 만든다.
- **낭만강호** — 무협 테마 모바일 RPG.

> **시사점**: 이 축의 게임들은 대체로 **아트보다 "정보 배치와 문체"로 무협을 판다**. 우리는 마감이 짧으므로 이쪽 비용 대비 효과가 가장 높다 — 초식 이름·구결·판정 등급 명칭의 **한자 조판**(세로쓰기, 낙관, 서체 대비)만 정리해도 화면이 즉시 무협이 된다.

## 5. 축 E — 입력 · 판정 피드백

### Sifu / Absolver
- Sifu 는 **의도적으로 빈약한 UI** — 공간 마커·버튼 프롬프트를 늘리면 게임의 정체성이 깨진다고 봤다. 대신 진입 장벽이 높아졌다는 비판을 감수했다.
- 다수 적 상황의 판독성은 **"티켓 시스템"** 으로 푼다 — 한 명만 주 공격자, 나머지는 대기. UI 가 아니라 **설계로 판독성을 확보**한 사례.
- Absolver 는 스탠스 전환 기반 콤보 덱. 각 스탠스가 속도·강도·방향이 다른 기술 3+1개를 가진다.

> **시사점**: 우리 6단 판정(완파/우세/상쇄/열세/역파/피격)은 **6단계를 색만으로 구분하면 실패한다** (접근성 원칙 위반 + 순간 판독 불가). 색 + **형태** + **위치** + **글자 크기** + **사운드 피치**를 함께 쓰는 다중 부호화가 필요하다. 특히 완파↔역파처럼 의미가 정반대인 쌍은 시각적으로 대칭 배치하는 게 유리하다.

### 리듬게임 · Patapon (시퀀스 입력)
- Patapon: 4비트 조합 커맨드를 리듬에 얹어 입력. **입력의 흐름 자체를 게임의 리듬으로 만든 사례** — 우리 "후보 필터 시퀀스"와 구조가 가깝다.
- 노트 하이웨이의 **판정 영역(Judgement Area)** 개념: 입력이 평가되는 구역을 화면에 명시적으로 그린다. 우리 시퀀스 입력에서 "지금 몇 번째 글자를 받고 있고, 남은 후보가 무엇인가"가 이 판정 영역에 해당한다.
- 피드백 타이밍 기준: **입력→시각 응답 16ms(60fps 1프레임) 이내**, **500ms 무반응은 플레이어가 "고장"으로 인식**.

## 6. 종합 — 그래픽 스타일 후보 3안

| | ① 먹 실루엣 (Ink Silhouette) | ② 수묵 카툰 (Ink Cartoon) | ③ 픽셀 무협 |
|---|---|---|---|
| 캐릭터 | 단색 먹 실루엣 + 붓질 아웃라인 | 굵은 붓선 + 채색 2~3톤 | 도트 스프라이트 |
| 배경 | 수묵 산수 3~4레이어 패럴랙스 | 같음 (채도 조금 더) | 도트 타일 |
| AI 에셋 난이도 | **가장 낮음** (실루엣은 프롬프트 편차에 강함) | 중 (캐릭터 일관성 이슈) | 높음 (도트는 AI 생성 품질 편차 큼 + 수작업 보정 필수) |
| 무협 톤 | 강함 | 강함 | 중 |
| 아이들 장르 친화 | 중 (다소 무거움) | **강함** | 중 |
| 판정 이펙트와의 충돌 | **없음** (캐릭터가 무채색) | 있음 (색 예산 경쟁) | 있음 |
| 애니메이션 비용 | 낮음 (실루엣은 프레임 적어도 성립) | 중 | 높음 (프레임 수가 곧 품질) |
| 마감(9/7) 적합성 | **최상** | 중 | 낮음 |

**권고: ① 먹 실루엣을 주 톤으로 하고, 아이들 장르의 친근함은 UI 레이어(둥근 카드·따뜻한 금색 액센트·과장된 숫자 팝)에서 담당시킨다.**

근거 — (a) 캐릭터 실루엣 ↔ 배경 디테일의 역할 분리가 OFDP2·Shadow Fight 2 양쪽에서 검증되었고, (b) 무채색 캐릭터가 6단 판정 이펙트의 색 예산을 통째로 비워주며, (c) 남은 일주일 안에 AI 파이프라인으로 뽑아 일관성을 확보할 수 있는 유일한 노선이고, (d) 현재 다크 팔레트(`--bg:#0e1116`, `--gold:#ffd166`)를 거의 그대로 쓸 수 있어 #24 결과물과 충돌하지 않는다.

기각 사유 — ②는 캐릭터 일관성 확보에 반복 생성 비용이 크고 판정 이펙트와 색이 경쟁한다. ③은 도트가 AI 생성에 가장 안 맞고, 프레임 수가 곧 품질이라 애니메이션 예산이 감당 안 된다.

## 7. 구현 경로 (zero-dep HTML5 제약 하에서)

### 7-1. 배경 — 패럴랙스 3~4 레이어
- **3~4 레이어면 깊이 착시는 충분하다**는 것이 공통 권고. 그 이상은 비용만 는다.
- 배경 외 레이어는 전부 **투명 PNG**여야 합성이 성립한다.
- 성능: 변하지 않는 레이어는 **오프스크린에 1회 렌더 후 오프셋만 바꿔 blit**. 캔버스를 쓸 경우 레이어별 다중 캔버스가 프레임당 갱신 픽셀 수를 줄인다.
- **우리 상황에서는 캔버스가 아니라 DOM/CSS 가 유력**하다 — #24 의 `transform: scale()` 스테이지 안에서 `background-position` 또는 `translate3d` 로 레이어를 밀면 되고, 모듈 추가 없이 `index.html` CSS 만으로 끝난다. 저사양 기기 대비로 **50fps 미만이면 패럴랙스를 끄는 조건부 렌더링**이 권고된다.
- ⚠️ #24 리스크 항목과 연결: `transform: scale` 컨테이너 안에서 `position: fixed` 는 스테이지 기준으로 갇힌다. 배경 레이어는 스테이지 자식으로 `position: absolute` 배치할 것.

### 7-2. 캐릭터 애니메이션 — 스프라이트 시트 우선
- **스프라이트 시트**: 프레임 크기와 동일한 컨테이너 + `background-image` + `background-position` 을 스텝 애니메이션. **순수 JS/CSS 로 가능, 의존성 0**. 정해진 동작 세트에 최적.
- **스켈레탈**: 뼈대 계층으로 동적 포즈. 유연하지만 런타임 라이브러리(pixi-spine 등)를 부르므로 **우리 zero-dep 계약과 충돌**.
- 결론: **스프라이트 시트 + CSS `steps()`**. 실루엣이라 프레임당 4~6장으로도 성립한다(§6 근거 d).
- 아키텍처 계약 준수: 애니메이션 코드는 전부 `src/ui/` 아래, 그것도 harness-import 4개 모듈(`sequence-input`·`match`·`session`·`wiring`) **바깥**에 둔다. 화면이 wiring 번들 위에 자기 렌더를 얹는 기존 방향(`composeHooks`)을 그대로 따를 것.

### 7-3. 게임필(juice) — 투입 대비 효과 순
공통 권고 순위 그대로:
1. **화면 흔들림** — 최고 효과/최저 비용. 지수 감쇠 랜덤 오프셋. (스테이지 래퍼가 아니라 `#screen` 에 걸어야 레터박스가 안 흔들린다)
2. **히트스톱** — 타격 순간 수 프레임 정지. 구현 난이도 사실상 0.
3. **히트 플래시** — 피격자 스프라이트를 흰색/붉은색으로 순간 플래시.
4. 파티클, 그리고 **피치 랜덤화(±10~15%) 사운드** — 반복 피로 방지.
- "예비동작 → 임팩트 히트스톱 → 피격자 머티리얼 플래시" 3단이 근접 타격의 무게감을 만든다.

## 8. 현재 화면과의 격차

현재 `index.html` 은 다크 카드 리스트 = **관리 대시보드 톤**이며, 세계관·타격감·캐릭터가 전부 부재하다. 위 조사에 비춘 격차:

| 격차 | 근거 축 | 후속 작업 후보 |
|---|---|---|
| 화면에 캐릭터·배경이 없다 | A, B | 대련 화면 아레나 아트 레이어 도입 (실루엣 2인 + 패럴랙스 3레이어) |
| 시각 언어가 장르와 무관 | C-1 | 팔레트·서체·버튼 형태를 무협 기호로 재정의 (한자 조판·낙관·먹 텍스처) |
| 6단 판정이 다중 부호화가 아님 | E, C-6 | 판정 등급별 색+형태+위치+크기+사운드 매핑표 신설 |
| 입력 시퀀스의 "판정 영역"이 명시적이지 않다 | E | 후보 필터 진행 상태의 전용 표시 영역 설계 |
| 타격 피드백(흔들림/히트스톱/플래시) 부재 | §7-3 | juice 3종 도입 — 가장 싼 체감 개선 |
| 검증 도구가 게임 UI와 섞여 있(었)다 | C-2 | #24 에서 스테이지 밖 분리로 이미 해소 |

**작업 순서 권고**: #24 완료 → (a) 팔레트·조판 재정의 + juice 3종 (코드 변경 작음, 체감 큼) → (b) 아레나 아트 레이어(배경 패럴랙스) → (c) 캐릭터 실루엣 스프라이트 + 애니메이션. (a)와 (b)는 에셋 없이도 착수 가능하므로 AI 에셋 생성과 병렬로 돌릴 수 있다.
