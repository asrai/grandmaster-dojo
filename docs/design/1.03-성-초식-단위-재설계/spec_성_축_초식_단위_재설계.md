## 개요

성(成)의 단위를 **무공 → 무공 초식**으로 내려 초식마다 1~12성 단일 게이지를 갖게 하고 (숙련도 0~100% 폐기·흡수), 전수 이후 구간에 **제자 수련(병렬 방치) + 파견 임무(B-1 고정 / B-2+ 랜덤)** 루프를 붙이며, **A-4 도전자 신설**로 4번째 초식(파운현월)과 절초(δ 월영자)에 무대를 준다. 목적 6: (a) 초식 간 격차를 정적 정보에서 성장 축으로 (b) 손의 투자와 화면의 보상 일치 (c) 「무엇을 대성시킬까」를 희소한 선택으로 (d) 숙련/성 2중 게이지 해소 (e) 전수 이후 성장 축 연결 (f) 4식·절초에 무대.

**운영자 판정 기준 지시** (본 spec 전체를 구속): ① kill (d) 사이클 시간 제한은 염두에 두지 않는다 — 예산을 이유로 한 콘텐츠 삭감·규칙 완화 불채택 ② 지인 kill 판정 범위 = **첫 파견(B-1)까지** — B-2 이후·제자 방치 루프는 구현하되 판정하지 않고 로그로 셀프 관측.

**현행 규칙 SoT 관계**: [[spec_프로토타입_v2_통합_PRD]] 의 성·숙련·해금·전수·제자·파견 계열 REQ 를 본 spec 이 대체한다 (§ 구현 스펙 말미 「1.01 대체 맵」). 판정 수식 SoT 는 여전히 [[13. 일대종사/1. 구상/공방 판정 설계|공방 판정 설계]] — `gradeOf` (6단 판정·파해·속성 삼각) 는 **무변경**.

> 통합 안건 — `## 구현 스펙` 을 brief § 내용 ①~⑩ 축의 서브시스템 sub-section 으로 구조화 (순서 = 의존 순서). REQ 번호대는 **701~799** (1.01 spec 의 101~606 과 겹치지 않게 — build 가 두 spec 을 함께 읽을 때의 오참조 방지). REQ ID 는 spec 문서 내 유일. `(depends:)` 는 데이터/구조 의존만.

## 구현 스펙

### ① 성 = 초식 단위 단일 게이지 (숙련도 흡수, 사부·제자 동형)

### 요구사항 (EARS)

- **REQ-701** *(Ubiquitous)*: The system shall 초식 단위 **성 1~12** 를 단일 게이지로 관리한다 — 성이 곧 그 초식의 숙련도이자 위력. 숙련도(0~100%)·무공 단위 성·성 포인트·입문 개념은 **소멸** (1.01 REQ-301·304·310 대체). 같은 무공 안에서도 초식마다 성이 다르다.
- **REQ-702** *(Ubiquitous)*: The system shall 사부 성 적립을 3단 구조로 한다 — **1~7성**: 수련 + 대련 병행, 적립률 차등 (시드: 수련 3회 = 1성 · 대련 유효 성공 1회 = 1성) / **8~10성**: 대련 유효 성공 **전용** (수련 적립 무효) / **11성**: 그 초식으로 결정타 1회 / **12성**: 그 초식으로 완파 1회. 계단 비용은 하네스 시뮬 확정 (§ 데이터 구조). *(depends: REQ-703, REQ-704)*
- **REQ-703** *(Ubiquitous)*: The system shall 대련·파견 적립 단위를 **유효 성공** (판정 order ≤ 상쇄, 현행 `isEffectiveSuccess` 게이트 승계) 으로 한정한다 — 발동 횟수 기준 금지 (판정 무시 난사가 최적이 되는 것을 차단). 수련 모드 성공 (창 내 완주) 은 수련 적립률로만 계상한다.
- **REQ-704** *(Event-driven)*: When 결정타 (승리를 확정한 마지막 타격) 또는 완파가 발생하면, the system shall 11·12성 계단을 **순차·비소급** 으로 판정한다 — 10성 상태에서 그 초식으로 낸 결정타만 11성, 11성 상태에서 그 초식으로 낸 완파만 12성. 한 초는 최대 1계단 (10성 상태의 완파 결정타도 11성까지), 이전 구간의 결정타·완파 이력은 소급하지 않는다. (역질문 확정 2026-09-02)
- **REQ-705** *(Ubiquitous)*: The system shall 제자 성 적립을 사부와 **동형** 으로 한다 — 「실전」의 자리에 파견: **1~7성** 제자 수련 + 파견 병행 (적립률 차등) / **8~10성** 파견 전용 / **11·12성 없음** (제자 상한 10성 — 결정타·완파는 자동 전투가 하지 않는 판단). *(depends: REQ-702)*
- **REQ-706** *(Unwanted)*: If 7성 초식에 수련 (사부) 또는 제자 수련의 적립이 시도되면, then the system shall 적립을 무효로 하고 `rank_wall{actor, style, at_rank: 7, attempted: train}` 을 로깅한다 (8성 벽 — 실전으로 미는 장치). *(depends: REQ-702, REQ-705)*
- **REQ-707** *(Ubiquitous)*: The system shall 성 게이지를 **연속 막대 + 계단 눈금 12** 로 그린다 — 다음 성까지의 진척이 막대로 차오르고 계단마다 눈금 점등, 성 숫자는 막대 옆 배지 병기. **11성 눈금 = 「결정타 필요」 · 12성 눈금 = 「완파 필요」 표식** 으로 형태를 다르게 (규칙이 화면에서 읽히게). 현행 숙련 막대 표현의 승계 — 신규 아트 비용 0. *(depends: REQ-701)*
- **REQ-708** *(Event-driven)*: When 대련이 끝나면, the system shall 결과 화면에 **어느 초식이 결정타였는지** 를 표시하고 `finish{style, challenger, intended}` (노린 초식과 실제 일치 여부) 를 로깅한다 — 결정타 통제 불가는 의도된 난이도이고, 해소 대상은 인과의 불투명성뿐이다. *(depends: REQ-704)*

### ② 해금·원터치·파급 개정

### 요구사항 (EARS)

- **REQ-711** *(Event-driven)*: When N식 성이 **5성** 에 도달하면, the system shall N+1식 학습을 도장 「배우기」 에서 해금한다 (재화 게이트 없음 — 1.01 REQ-303 의 「숙련 100%」 대체). 해금(5성)과 원터치(7성)의 **분리**가 「새 초식을 배우러 갈까, 이 초식을 마저 밀까」 선택을 만든다. *(depends: REQ-701)*
- **REQ-712** *(State-driven)*: While 실전 응수 창에서 **<7성** 초식이 후보일 때, the system shall 딜레이드 힌트를 유지한다 (키마다 `hintDelay` 0.5s 뒤 점등, 수련 0 — 1.01 REQ-108 의 「미완성 <100%」 대체). *(depends: REQ-701)*
- **REQ-713** *(Ubiquitous)*: The system shall 성 계단 해금을 다음으로 한다 — **2성 = 실전 장착 가능** (1.01 `equipMasteryPct` 대체) · **7성 = 원터치** (1.01 REQ-109 의 「숙련 100%」 대체, oneTap 메커닉 무변경). *(depends: REQ-701)*
- **REQ-714** *(Ubiquitous)*: The system shall 1.01 REQ-305 의 **입문 전 자동 자리 양보를 폐지** 한다 — 입문 개념 소멸로 근거가 사라졌고, 자동 교체는 A-4 슬롯 압박(목적 c)을 죽인다. 장착은 2성부터 유저 선택, **빈 슬롯 자동 채움만 유지**, 슬롯 수 3 유지. (spec 위임 — § 설계 결정)
- **REQ-715** *(Ubiquitous)*: The system shall 수련 모드 메커닉을 승계한다 (1.01 REQ-308 — 실전과 동일 창 `T`, 힌트 즉시, 실패 무벌) — 적립만 성 축 (REQ-702 수련 적립률) 으로 바뀐다.

### ③ 위력 = 성 × 속성 — 도전자에게도 성이 있다

### 요구사항 (EARS)

- **REQ-721** *(Ubiquitous)*: The system shall `powerOf(rank)` 의 입력을 **그 초식의 성** 으로 바꾼다 (무공 성 → 초식 성). 내공 `N = 1 + powerPerRank × 성` 수식 자체는 무변경. 판정 등급 산출 (`gradeOf` — 파해 1:1·속성 삼각) 무변경. *(depends: REQ-701)*
- **REQ-722** *(Ubiquitous)*: The system shall **도전자에게 성을 부여** 한다 — 해상도 = 도전자별 성 1개 (그 도전자의 모든 초식 공통), `foePower = powerOf(도전자 성)` 으로 `challengerPower` 를 **폐기·통합** 한다. 난이도 곡선을 성으로 표현 (A-1 → A-2 → A-3 → A-4 → B 상승, 시드 § 데이터 구조). 상대 성은 **모델에 존재하되 화면에 숫자로 띄우지 않는다** (모델과 표시는 별개 축). *(depends: REQ-721)*
- **REQ-723** *(Ubiquitous)*: The system shall 성 차로 판정 등급을 뒤집지 않는다 — 등급 승격은 보류 (MVP 밖 ⓐ). 검산: 12성 열세 0.32d < 1성 우세 0.63d. 성 데이터가 양변에 존재하므로 후속 도입 시 데이터 준비는 끝나 있다. *(depends: REQ-722)*

### ④ 사부 대련 확장 — A-4 신설 · 재대련

### 요구사항 (EARS)

- **REQ-731** *(Ubiquitous)*: The system shall 도전자 **A-4** 를 신설한다 — 적 초식 **α 벽산도 · γ 질풍각 · δ 월영자 (절초)**, A-3 승리 후 해금. δ 를 사부가 처음 만나는 도전자다. 파해표 (1:1 무결성 하네스 유지): 유운보(쾌)→α · 적운압정(강)→β · 행운유수(정)→γ · 파운현월(쾌)→δ. 완파 무대: 유운보 A-1~A-4 / 적운압정 A-2·A-3 / 행운유수 A-3·A-4 / 파운현월 **A-4 만**. 사부 대련 4판 = 결정타 4회를 초식 4개에 1:1 배분 가능. *(depends: REQ-722)*
- **REQ-732** *(Event-driven)*: When A-4 (및 절초 보유 도전자 일반) 의 도전자 예고 화면이 뜨면, the system shall 그 도전자와의 **대면 이력에 따라 절초를 공개** 한다 — **첫 대면**(재대련 회차 0)은 절초의 **존재만 소문**으로 남기고, **재대련부터** 절초 δ 의 이름과 **파해 대상 초식을 공개** 한다. 절초는 역파라는 특별 벌칙을 가진 유일한 초식이므로 그것만 예외 공개이고 (역파는 회피 대상 — 답은 가르치는 것이지 감쇠가 아니다, 문제 1ⓐ), 첫 대면을 소문에 묶는 것은 싸워 본 적 없는 상대의 초식을 아는 것이 성립하지 않기 때문이다. 전면 비공개가 아닌 이유는 그러면 첫 대면이 반드시 역파를 한 번 맞고 시작하기 때문이다. 개정 근거 = [[spec_화면_UI_아트_재설계]] REQ-894·883. *(depends: REQ-731)*
- **REQ-733** *(Ubiquitous)*: The system shall A-4 도전자 성을 A-3 보다 **한 단계만** 올린다 — 절초의 존재 자체가 난이도이므로 수치까지 올리면 이중 부담 (문제 1ⓑ). *(depends: REQ-722, REQ-731)*
- **REQ-734** *(Event-driven)*: When 유저가 이미 이긴 도전자와 재대련하면, the system shall 그 도전자의 성을 **+1 누적** 시킨다 (초회 대면 +0, **상한 시드 +3**) — 파밍 자연 종료 + 「여기서 더 캘까 / 다음으로 넘어갈까」. 상한 필수 근거: 파운현월 완파는 A-4 에서만 가능하므로 상한 없는 누적은 A-4 반복 실패가 파운 12성을 영구 봉쇄한다. 재대련 항목을 도장에 명시 노출하고, **재대련 승리는 재화(coins) 보상을 주지 않는다** (파밍 루프 차단, 문제 2). `rematch{challenger, foe_rank, attempt_n}` 로깅. *(depends: REQ-722)*
- **REQ-735** *(Ubiquitous)*: The system shall **A 밸런스 게이트** 를 재검증한다 — 각 차수 도달 시점의 장착·성으로 A-1~A-4 를 초 상한 안에서 이길 수 있는지 하네스 시뮬 (1.01 REQ-507 승계·A-4 확장), 못 이기면 해당 차수 HP·도전자 성 하향. *(depends: REQ-731)*
- **REQ-736** *(Event-driven)*: When 유저가 슬롯을 바꾸면, the system shall **도장의 행 버튼(「장착」·「해제」)에서만** 그것을 받는다 — 도전자 예고 화면의 in-place 교체는 REQ-886(1.02)이 철회했다. 장착 가능 초식이 10 종을 넘으면 「어느 칸을 비울지 → 무엇을 넣을지」의 2단 선택을 예고 화면이 감당하지 못하고, 예고 화면의 물러나기가 이미 도장으로 가므로 동선 손실이 없다. `slot{action, styleId, challenger}` 로깅은 그대로이며 `challenger` 는 예고 화면 밖의 교체를 뜻하는 `null` 이 된다. *(depends: REQ-731)*

### ⑤ 제자 파견 = 임무 · 2단화 (B-1 / B-2+)

### 요구사항 (EARS)

- **REQ-741** *(Ubiquitous)*: The system shall **B-1 (1차 파견) 을 고정 상대** 로 유지한다 — 현행 B 구성 (α·γ + 절초 δ) · **1.01 REQ-506 하한 승계**: 1성 제자가 무지시 자동으로도 이긴다 (하네스 게이트). 랜덤화 금지 — 최악 조합 패배가 무패 보장을 깬다. 전수 직후의 통쾌함이 지연 없이 온다.
- **REQ-742** *(Ubiquitous)*: The system shall **B-2 이후를 랜덤 임무** 로 한다 — `foe_set` 을 적 초식 아키타입 풀 (α·β·γ·δ) 에서 임무마다 랜덤 구성하고 (δ 포함 가능 — 역파의 제자 무대), 임무 도전자 성은 난이도 곡선 데이터로 상승시킨다. 눌러앉기 구조적 차단 (대련의 재대련 문제가 파견에는 발생하지 않는다) + 「지금 제자 성으로 보낼까」 가 매 파견의 판단. M1 은 골격 (풀 = 기존 아키타입 재사용, 임무 종류 다수·준보스/보스는 M2). *(depends: REQ-722, REQ-741)*
- **REQ-743** *(Unwanted)*: If 제자의 **전 초식 최소 성** 이 B-2 권장 성 (시드 5) 미만이면, then the system shall 파견 버튼을 **비활성화** 한다 (하드 잠금 — 확인 팝업 아님: 팝업은 습관적으로 넘겨져 실패를 고를 경로를 남긴다) + 부족한 초식을 표시한다. (기준 = 최소 성, 역질문 확정 2026-09-02 — 뒤처진 초식이 잠금을 쥐어 수련 지정과 정합) *(depends: REQ-742, REQ-751)*
- **REQ-744** *(Event-driven)*: When 파견이 종료되거나 관전 중 이탈하면, the system shall `dispatch{stage: B-1|B-2+, foe_set, disciple_ranks, locked_until, result: win|loss|abort}` 를 로깅한다 — B-1 무패 보장·B-2 잠금·랜덤 조합별 승패의 분리 식별. 관전 중도 이탈은 `abort` 로 같은 스키마에 남기고(재진입은 새 판), 판독기는 이를 그대로 실으면서 승률류 분모에서는 뺀다 — 없던 판으로 두면 「파견 N회 중 M승」의 N 이 조용히 흔들린다. 한 판은 결과 항목을 하나만 내므로 종료 뒤의 이탈은 남기지 않는다. *(depends: REQ-742)*
- **REQ-745** *(Ubiquitous)*: The system shall 파견 실행 규칙을 승계한다 — 항상 성공 (1.01 REQ-402) · 자동 선택 우세→상쇄→역파 회피 (REQ-403) · 선택적 지시·반짝임 (REQ-404·405) · 관전 기본 (REQ-407). 성 참조만 초식 단위로 바뀐다. *(depends: REQ-721)*

### ⑥ 제자 수련 — 병렬 방치 루프, 초식 지정

### 요구사항 (EARS)

- **REQ-751** *(Ubiquitous)*: The system shall **제자 수련** 을 제공한다 — 유저가 **수련시킬 초식을 지정** 해 걸어두면 실시간 경과로 그 초식의 제자 성이 오른다 (1~7성 구간만, REQ-705·706). 파견(자동 전투)이 주지 못하는 초식별 성장 통제권의 회복 (문제 4). *(depends: REQ-705)*
- **REQ-752** *(Ubiquitous)*: The system shall 제자 수련을 **병렬** 로 돌린다 — 타이머가 도는 동안 사부의 수련·대련을 차단하지 않는다 (직렬 대기는 사이클을 빈 시간으로 가른다). 화면 신설 없이 **도장 제자 카드에 진척 막대 1개 + 초식별 성 4개 나란히** (어느 초식이 뒤처졌는지 한눈에). *(depends: REQ-751)*
- **REQ-753** *(Ubiquitous)*: The system shall 수련 시간을 **방치 루프로서 의미 있는 길이** 로 둔다 (분 단위 축소 금지 — 짧으면 재방문 동기와 M2 가속 아이템이 붙을 자리가 사라진다). 기존 `simTrainSeconds`·`simEfficiency` 수련 시뮬 파라미터의 확장 — 그 방치 계산을 제자 성에 연결한다. 가속 아이템·재화 소모는 M2. 판정 세션의 대기 지루함은 판정 범위 (REQ-792) 로 해소하며 게임 수치를 줄이지 않는다. *(depends: REQ-751)*
- **REQ-754** *(Event-driven)*: When 제자 수련으로 성이 오르면, the system shall `disciple_train{style, from, to, elapsed_ms, master_activity}` 를 로깅한다 — 체감 시간 + 병렬성 (사부가 그동안 무엇을 했는지) 검증. *(depends: REQ-751)*

### ⑦ 전수 개정

### 요구사항 (EARS)

- **REQ-761** *(Event-driven)*: When 무공의 **전 초식이 12성** 이고 제자 무공 슬롯에 여유가 있어 유저가 전수를 실행하면, the system shall 무공을 제자에게 복사한다 — 전수 단위 = 무공 (전 초식 통째, `learned` 필터 없음 — #38 D8 유지) · **제자 시작 성 = 전 초식 1성** (사부 성 비상속 — 제자가 커나가는 재미가 전수 이후 구간의 동력). `transmit{art, styles: [{id, rank}], t_ms}` 로깅. *(depends: REQ-701, REQ-704)*
- **REQ-762** *(Ubiquitous)*: The system shall 전수 연출·단계 라벨 규칙을 승계한다 (1.01 REQ-307 연출·REQ-309 문하생→고수). 12성 배지 문구 「완벽히 깨달음」 은 초식 단위 성으로 자연 성립 (입문 동치 주석은 소멸). *(depends: REQ-761)*

### ⑧ 역파 감쇠 + 관통 하한

### 요구사항 (EARS)

- **REQ-771** *(Ubiquitous)*: The system shall 역파 피격량을 성 차로 감쇠한다 — `역파 피격 = 상대 피해 × max(관통 하한, 1 − decayPerRank × max(0, 내 초식 성 − 상대 초식 성))`, 관통 하한 시드 40%. 하한의 목적은 하나 — **「절초는 무서워야 한다」** (역파는 절초의 유일한 발생원). 이 값을 난이도 완충 장치로 인용하지 않는다 (순환논법 — 시뮬 목적함수 이원화 금지). *(depends: REQ-721, REQ-722)*
- **REQ-772** *(Ubiquitous)*: The system shall 역파를 **회피 대상** 으로 유지한다 — δ 예고가 뜬 초에 파해 대상 초식을 안 내면 발생하지 않는다 (1차 해법 = REQ-732 예고 공개, 감쇠는 맞았을 때의 성장 보상). 무대 = A-4 (사부) + 임무 (제자 — 제자 수련의 보상: 키워 보내면 덜 아프게 맞는다). *(depends: REQ-732, REQ-771)*

### ⑨ 개발자 치트 메뉴

### 요구사항 (EARS)

### 데이터 구조

**BALANCE 개정** (`src/balance.data.json` — 전 항목 데이터 드리븐 유지):

- **폐기**: `masteryTrainPct` · `masteryFullPct` · `threshold` · `rankPtsPerStyle` · `rankStep` · `rankStepMult` · `equipMasteryPct` · `challengerPower` (→ 도전자 성으로 통합)
- **의미 유지**: `powerPerRank` (입력만 초식 성) · `trainGraduateHits` 류 수련 메커닉 · `discipleStartRank` 1 · `discipleRankMax` 10 · `discipleFireRatio` · `hp` (+ A-4 행 추가) · 판정·창·선기·빈틈 전 항목
- **신설 (전부 시드 — 하네스 시뮬 확정 대상)**: 성 계단 비용 (1~7성 수련 3회/대련 1회 · 8~10성 대련 2회) · 수련 적립 상한 7성 · 장착 2성 · 해금 5성 · 원터치 7성 · 도전자 성 (A-1 1 · A-2 2 · A-3 3 · A-4 4 · B-1 2 · B-2+ 곡선) · A-4 HP (시드 90) · 재대련 성 +1 · 재대련 누적 상한 +3 · B-2 권장 성 5 (전 초식 최소 성 기준) · 제자 수련 1성당 시간 (시드 1800s) · 역파 `decayPerRank` (시드 0.05) · 역파 관통 하한 0.4 · kill (b) 최소 수동 창 표본 20 · B-2+ 임무 풀 테이블 (아키타입 조합·성 곡선)

> **미해소 수치는 시뮬 산출로만 확정한다** — #38 D3 이 손 추정 시드표를 그대로 밀어넣어 사이클이 481s 가 된 전례 (`balance-log` 0-e). 위 시드값은 하네스 사이클 시뮬 (봇 v2 손 모델) 산출로 교체 후 커밋하며, 단 **운영자 판정 기준 지시 ①** 에 따라 시뮬 목적함수에 kill (d) 300s 를 제약으로 넣지 않는다 (관측치로만 기록).

**도전자 데이터 확장** (1.01 REQ-503 대체): A-1 (α) · A-2 (α·β) · A-3 (α·β·γ) · **A-4 (α·γ·δ)** — 파해를 하나씩 가르치는 학습 계단이므로 **사부 대련은 랜덤화하지 않는다**. B-1 = 현행 B 고정 (α·γ+δ). B-2+ = 아키타입 풀 랜덤 조합. 도전자별 `rank` 필드 신설 (`challengerPower` 폐기).

### 상태 머신 / 핵심 로직

- 상태기계 골격 유지 (도장 ↔ 사부 대련 ↔ 전수 ↔ 파견) + 확장: 대련 진입이 A-1~A-4 + 재대련 목록으로, 파견이 B-1/B-2+ 스테이지로, 도장에 제자 수련 지정 상태 추가 (병렬 — 상태기계를 점유하지 않는 타이머).
- 순수 함수 (헤드리스 하네스 대상) 개정: `powerOf(초식 성)` · 성 적립 (3단 구조 + 순차·비소급 계단) · 역파 감쇠 · 재대련 성 누적 · B-2 잠금 판정 (전 초식 최소 성) · 제자 수련 경과 계산 · 전수 조건 (전 초식 12성). `gradeOf`·prefix-free·파해 1:1 assert 무변경.
- 사이클 이정표 (판정 범위 = B-1 종료): 배움 (2성 장착) → 첫 갈림길 (5성 해금 vs 7성 원터치) → 8성 벽 (도장을 나선다) → 재대련의 무게 → A-4 (절초·슬롯 압박) → 11·12성 (결정타·완파) → 전수 → B-1 (무패) → [판정 경계] → 제자 수련 → B-2+ 랜덤 임무.

### UI / UX 명세

- **성 게이지** (REQ-707): 연속 막대 + 계단 눈금 12 + 성 배지, 11·12 눈금 별도 표식. 초식 카드 단위 (무공 카드 「N성」 배지는 소멸 — 숙련 막대 + 성 배지 이중 표시 해소).
- **도장**: 재대련 항목 (이긴 도전자 목록 + 회차·강화 표시, REQ-734) · 제자 카드 = 수련 지정 UI + 진척 막대 + 초식별 성 4개 (REQ-752) · 배우기 (5성 해금 표시).
- **도전자 예고 화면**: 절초 파해 대상 공개 (REQ-732). 슬롯은 표시 전용이고 교체는 도장이 진다 (REQ-736 개정).
- **파견**: B-2 잠금 = 버튼 비활성 + 권장 성·부족 초식 표시 (REQ-743). 관전 기본 유지.
- **대련 결과 화면**: 결정타 초식 표시 (REQ-708).
- **치트 패널**: 게임 화면 밖, 기본 숨김 (REQ-781).
- 아트·사운드 실파일 없음 — 코드 렌더 + 합성음 폴백 유지 (신규 아트 비용 0).

### 기술 의존성

- HTML5 vanilla JS · `src/` DOM-free 계약 유지 — 성 적립·역파 감쇠·잠금 판정은 순수 함수로 `core.mjs`/`balance.mjs` 층에, 제자 수련 타이머는 주입 콜백 (`now`) 기반으로 하네스에서 시간 가속 가능하게.
- `core.mjs` 성장 로직 **3회차 재설계** — 로드맵 비고의 redesign 게이트 대상 (SoT 선행 = 본 spec, 침습 패치 누적 금지).
- 판정표·수식 변경 없음 — 하네스 기대값 변경은 성 적립·역파 감쇠 계열에 한정, 같은 커밋.

## 스코프

### MVP 포함

- 초식 단위 성 1~12 단일 게이지 (숙련도 폐기) · 사부/제자 동형 3단 적립 · 순차·비소급 11·12성 계단
- 해금 5성 / 장착 2성 / 원터치 7성 / 딜레이드 힌트 <7성
- 도전자 성 (`foePower`) · A-4 신설 · 재대련 (+1, 상한 +3, 무보상) · 예고 화면 슬롯 교체 + 절초 파해 공개
- 파견 2단화 (B-1 고정·무패 / B-2+ 랜덤 임무 · 최소 성 하드 잠금) · 제자 수련 (병렬 방치·초식 지정)
- 전수 = 전 초식 12성, 제자 1성 시작 · 역파 성 차 감쇠 + 관통 하한 · 개발자 치트 메뉴
- 로그 스키마 재정합 (sv:2 + 신설 5종) · kill (b) 재확정 · 판정 범위 B-1

### Phase 2 이관 (범위 밖)

- 성 차에 의한 판정 등급 승격 (보류 — 응수 창 판단 부하 2배, 차후 밸런스 재검토)
- 상대 성의 UI 숫자 표시 (모델에는 존재)
- 임무 종류 다수 · 스토리 연계 준보스/보스 (M2 — M1 은 B-2+ 상대 랜덤화까지)
- 제자 수련 가속 아이템 / 재화 소모 (M2 BM 코어 경제)
- 제자 2명 이상 / 진법 (3막 콘텐츠)
