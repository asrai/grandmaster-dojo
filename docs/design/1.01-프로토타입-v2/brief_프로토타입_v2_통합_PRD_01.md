# 프로토타입 v2 통합 PRD — Brief

> M1 통합 spec 안건 (dotfiles #1532 — 프로토타입 기본값: 코어 루프 1개 · 단일 파일 코드베이스 → PRD 1개 + build 순차 이슈). 입력부 절(§ 내용 ①)은 `brief_후보_필터_시퀀스_입력부_01.md` 의 4섹션 + 페르소나 cycle 01 발굴(안건 1·2·4)을 흡수해 정정한 것. 판정 수식·파라미터의 SoT 는 볼트 [[13. 일대종사/1. 구상/공방 판정 설계|공방 판정 설계]], 컨셉은 [[13. 일대종사/0. 프로젝트 개요/1. 게임 제안서|1. 게임 제안서]] §5·§7.

## 목적

v0(`index.html` 1.2k 라인, 라운드 1 규칙 「예고 → 정답 시퀀스 1개 강제」)를 **v2 규칙의 1막→2막 1사이클**로 교체해, 제안서 §7 kill-criterion 을 **실제 플레이로 판정할 수 있는 한 덩어리**를 만든다. 이 프로토타입이 슈퍼센트 과제 제출물(마감 2026-09-07)이며 판정일은 2026-09-02 저녁이다.

검증하려는 재미 가설은 하나다 — **"손으로 익힌 초식이 자동화되는 순간이 보상이다"**. 그것을 성립시키는 네 조건이 곧 목적이다.

- **(a) 입력 = 선택 + 실행** — 후보 필터 입력으로 "무엇을 낼지"(첫 키)와 "어떻게 완주하는지"(꼬리)를 분리해 6단 판정이 판정할 대상을 만든다. 정답 1개 강제였던 v0 에선 우세/열세/역파가 존재할 수 없었다.
- **(b) 숙련 = 자동화 권한** — 같은 후보 리스트 위에서 힌트(0~30%) → 후보만(30~99%) → 원터치(100%) → 자동응수(100%+토글)로 정보량만 줄어드는 한 표면. "손이 기억한다"가 화면으로 읽혀야 한다.
- **(c) 슬롯 제한 → 전수 → 해방** — 슬롯 3 이 차서 새 비급을 못 배우는 압력이 전수를 강제하고, 전수 직후 분할 화면(제자 자동 + 사부 수련 + 커버)이 1사이클의 클라이맥스다.
- **(d) 자명성** — 튜토리얼 없이 첫 초식 발동 ≤ 60초 (kill (a)). 후보 필터가 웹 자동완성 문법이라 설명 없이 읽힌다는 가설.

**통합 1개로 만드는 이유** (분할 대비): 6 서브시스템이 한 상태기계의 부품이라 따로 만들면 통합 결함이 마지막에 나온다(여행자의 단어장 M1 작업 7 즉석 승격 — 6작업 `구현완료` 후 코어 루프 정합 결함 발견). 단일 파일이라 병렬 구현도 충돌만 낳는다. 대가(리뷰 diff 증대·측정 all-or-nothing)는 § 내용 ⑥ 의 서브시스템별 로그와 build 순차 이슈 분할로 상쇄한다.

## 내용

**MVP 스코프** (제안서 §7): 비급 1권 「유운검법」 4식 · 도전자 2명(적 초식 4, 파해 1:1) · 실전 슬롯 3 · 제자 1명 · 6단 판정 · 수련 시뮬 · 로그 내보내기. 1사이클 = 비급 입수 → 수련 모드 1식 → 도전자 A → 2·3식 학습 → 슬롯 가득 → 1식 전수 → 분할 화면 → 도전자 B(절초 공개 → 파해 장착) → 등급 상승. **범위 밖**: 오프라인 타임스탬프 정산·HMAC 세이브(M2) / 제자 2명·비급 2권·재화 싱크(M2) / 광고·IAP(M2~M4) / 아트·사운드 실파일(M3 — 코드 렌더 기호·Web Audio 합성 폴백) / 허초·변초·진법·창작(S1~S3).

**아키텍처 원칙**: `BALANCE` 단일 객체(파라미터 SoT, § 내용 ⑥ 표) + 상태기계 1개 + 초식/도전자 데이터 테이블 JSON + 로그 버퍼. 판정·숙련·전수는 **순수 함수**로 분리해 헤드리스 하네스가 DOM 없이 돈다(v0 헤드리스 검증 방식 승계). 서브시스템 ①~⑥ 은 이 함수 경계로 나뉘고, build 순차 이슈 분해도 이 경계를 따른다.

### ① 후보 필터 시퀀스 입력부

- 장착 = 실전 슬롯 3. 각 초식은 고유 방향 시퀀스 `↑↓←→` 3~5 길이. 응수 창 시작 시 후보 = 장착 전체, 키마다 `candidates = 입력 버퍼를 접두어로 갖는 장착 초식`. **후보 0 이 되는 키 = 오입력 무시**(버퍼·후보 불변, 피드백 연출만). 리셋은 **리셋 버튼**(모바일 고정 타깃 / 데스크톱 `Space`·`Esc`)만 — 자동 리셋 없음. **발동 = 후보 1개 ∧ 버퍼 == 시퀀스** → `fire{styleId, r}` 를 판정부 ② 에 전달.
- **응수 창 `T` — v0 실측 컨벤션 승계**: `T = 2.6 + 0.4 × (len − 3)` s (3/4/5길이 = 2.6/3.0/3.4s). v0 `windowMs` 2200/2600/3000 은 길이 **2/3/4** 에 붙어 있었고(`index.html:151-153`), 그 창으로 사람 속도 봇이 격파 19 · 실패 12 였다 — 이미 빠듯하므로 같은 길이엔 같은 창을 쓴다. [[13. 일대종사/1. 구상/공방 판정 설계|공방 판정 설계]] §6 의 `T = 2.0s` 는 **D3 튜닝 하한 목표**로 기록하고 초기값으로 쓰지 않는다(선기 `r` 은 `T` 정규화 비율이라 수식 무변경). 접근성 +30% 는 `T` 승수 파라미터로 노출만.
- **입력 소스 3중 통합**: 방향키 / WASD / 스와이프 → `onDirection(dir)` 단일 진입. 스와이프 = Pointer Events 단일 경로, 임계 24px, dominant-axis `|dx|:|dy| ≥ 1.5`. **모든 입력 시도는 피드백을 받는다** — 종류만 셋: *수락*(버퍼 진행) / *무시*(후보 0 — 셰이크 + 회색 화살표 튕김 + 둔탁음) / *미인식*(축 비율 미달 — 손가락 궤적 끝에 `?` 표시, 버퍼·후보 불변, 로그 `swipe_reject`). 무시와 미인식은 로그를 분리해 `ignore_rate` 가 "안 먹은 느낌"을 과소 계측하지 않게 한다.
- **후보 표시 표면**: 후보 아이콘(속성 3색 테두리 + 형태 ▲●■) + **첫 키 방향 문양 상시 내장**(비급 첫 키 배정 — 유운검법 = `↓`). 0~30%: 후보 아래 잔여 화살표 힌트 / 30~99%: 아이콘만 / 100%: 아이콘 탭 = 원터치(③). 후보 1 도달 순간 아이콘 중앙 확대 + 이름 1줄("유운보!") = 꼬리 진입 신호. 입력 버퍼는 한 줄(v0 `#seq` 재사용), 무시 키는 버퍼에 남지 않음.
- **실전 장착 조건 = 숙련 ≥ 30%** (수련 모드 통과 = 시퀀스 암기 판정). 따라서 실전 후보는 전부 유저가 외운 초식이고, 갈래를 잘못 들어 다른 초식으로 좁혀져도 그 잔여 시퀀스를 유저가 안다 — "그대로 완주 = 유효한 응수(속성 상성 판정)" 가 성립하는 근거.
- **포함 금지 규칙** `assertPrefixFree(styles[])`: 비급 로드·슬롯 장착 시 assert, 위반 시 장착 거부 + 콘솔 에러. ⑤ 데이터 검증 스크립트와 같은 함수.

### ② 6단 공방 판정부 (데이터 드리븐 + 헤드리스 하네스)

- 한 수 타임라인: 예고 0.5s(상대 초식 아이콘 + 속성 색 + 조짐) → 응수 창 `T` → 교차 판정 0s → 연출 0.5s. 대련 = HP 소진 또는 12수 → 잔여 HP 비교.
- 판정표(공방 판정 설계 §2-2 그대로): 파해 → **완파**(100% + 상대 빈틈) / 속성 승 → **우세**(60%/20%) / 동속성 → **상쇄**(내공차 × k) / 속성 패 → **열세**(20%/60%) / 상대 절초의 파해 대상을 냄 → **역파**(0/100% + 나 빈틈) / 미완주 → **피격**. 속성 삼각 쾌>강>정>쾌. 파해 관계가 삼각보다 우선.
- 수식: `D` = 길이별 10/14/20 · 내공 `N = 1 + 0.5 × 숙련%` · 선기 `1 + 0.3r` · 상쇄 `max(0, N나−N적) × D × k`(k=0.5) · 빈틈 = 1수 지속(상대 빈틈: 다음 수 아무 초식 완주 = 완파 취급, 예고 없음 / 나 빈틈: 다음 수 `T` −40%).
- **판정표·수식·파라미터 전부 `BALANCE` JSON 으로 외부화** — 하네스가 6단 × 빈틈 × 선기 전 조합을 순수 함수 `judge(mine, theirs, r, state)` 로 회귀(판정 등급·피해 정수·상태 전이 assert). 판정표 변경과 하네스 기대값은 같은 커밋.
- 정보 노출(§5): 상대 속성 색 항상 / 내 후보 속성 색 항상 / 파해 관계는 비급 구결 텍스트에만 / 상대 절초 1개는 도전자 예고에서 공개 / 잔여 시퀀스 힌트는 0~30% 만.

### ③ 숙련 4단계 · 실전 슬롯 3 · 전수 시연

- 숙련도 = 초식별 0~100%. 증가 = 수동 완주 성공(수련 모드·실전 공통, 판정 ≥ 상쇄), v0 `threshold` 승계 — 30% 도달 = 수련 모드 졸업(힌트 소멸·실전 장착 가능), 100% = 원터치 해금, 100% + 토글 = 자동응수(성공률 `p` = 내공 연동 0.6→1.0, 창의 45% 시점 시도).
- **원터치**: 100% 초식은 시퀀스 도중 후보 아이콘 탭으로 즉시 발동(잔여 생략) → `r` 은 탭 시점 → 자연스럽게 선기 만점 근접. "몸이 기억"이 숫자로 보상되는 곳.
- **실전 슬롯 3**: 장착 조건 숙련 ≥ 30%, 교체는 도장(대련 사이)에서만, 슬롯에서 빼도 숙련 보존. 슬롯이 차면 새 비급 학습 불가 → 100% 초식을 전수해 비운다.
- **전수 = 제자 앞에서 N회 시연 성공**(수련 모드 UI 재사용, N = `BALANCE.transmitReps` 초기 3). 성공 시 초식이 제자 슬롯으로 이동, 사부 슬롯 비움, 전수 스팅어(폴백 합성음) + 「전수」 연출 1.0s.
- 단계 라벨: 문하생 → 고수(첫 전수) — 프로토타입은 여기까지(사부·일대종사는 M2+).

### ④ 제자 1명 자동응수 + 사부 커버 분할 화면

- 전수 직후 화면이 **분할**: 제자 대련(작게, 자동) + 사부 수련(크게, 수동 — 다음 초식 학습). 제자는 전수받은 초식만 사용, 성공률 = 제자 내공(사부 × 0.6 시작), 창의 45% 시점 시도.
- **커버**: 제자 실패 시 알림(제자 패널 적색 + 진동) → 남은 55% 안에 사부가 그 초식 시퀀스를 수동 입력(사부 슬롯에 없어도 커버 입력은 허용 — 전수한 초식이라 유저가 안다). 커버 성공마다 제자 성공률 +Δ(`BALANCE.coverGain`). v0 실측(천붕각 4키 커버 3건 미커버 — 1650ms 에 4키 빠듯) 반영: 제자 시도 시점 `autoDelayRatio` 0.45 → **0.35 초기값**(커버 여유 65%).
- 제자 대련의 판정도 ② 와 같은 `judge()` — 제자용 판정 결과는 사부 HP 와 분리된 제자 HP 에 적용. 제자 패배 = 도전자 도주(재화 손실 없음, 프로토타입 단순화).

### ⑤ 비급 「유운검법」 4식 · 도전자 2명 데이터 · 도전자 예고

- 초식 테이블: id · 이름 · 한자 · 속성(쾌/강/정) · 시퀀스(3~5, 첫 키 `↓` 공유) · `D` · 파해 대상(적 초식 id) · 구결 텍스트(파해 힌트 포함). 4식 = 길이 3·3·4·5 분포로 꼬리 길이 등급 차이가 보이게.
- 도전자 A(유파 1, 적 초식 2, 절초 없음 — 첫 대련) / 도전자 B(유파 1, 적 초식 2 중 절초 1 공개 — 역파 위험 도입). 적 초식 4 는 각각 유운검법 1식과 1:1 파해 관계(비급 1권 = 상대 유파 1개의 파해 세트).
- **도전자 예고 화면**(대련 전): 유파명 + 절초 1개 아이콘·속성 → 유저가 슬롯 3 을 조정하는 준비 단계. 읽기·선택을 전투 밖으로.
- 검증 스크립트: `assertPrefixFree` + 파해 1:1 무결성(모든 적 초식에 파해 존재·유일) — 데이터 커밋마다 하네스에서 실행. 명명 관례 [[무공 초식 조사]] §2-5(LLM 사전 생성은 M2 파이프라인, 프로토타입은 수작업 4+4).

### ⑥ 검증 로그 스키마 · 수련 시뮬 · 사람 속도 봇 v2 · 파라미터 표

## 예상되는 플레이와 기대하는 재미

- **0~60초 (긴장)**: 비급 입수 → 수련 모드에서 유운보(↓→…) 힌트 따라 첫 완주. 예고 색을 보고 색이 이기는 후보를 고르는 첫 판단. 후보가 첫 키에 좁혀지는 것이 "검색창 자동완성"처럼 읽혀 설명 없이 첫 발동 — kill (a) 의 체감 지점.
- **1~3분 (숙달)**: 30% 넘으며 힌트가 사라지고 아이콘만 남는다. 첫 키 뒤 후보 1 확대 순간부터 꼬리는 손이 친다. 원터치가 열리면 선기 +30% 가 숫자로 돌아와 "빨리 끝내는 게 이득"이 체감. 열세·역파를 한 번 맞으면 "색을 봐야 한다"가 학습된다.
- **3~5분 (해방)**: 슬롯 3 이 차서 4식을 못 배운다 → 100% 된 유운보를 제자 앞에서 3회 시연 → 화면이 갈라지고 제자가 유운보를 대신 친다. 사부는 4식을 수련하고, 제자가 놓친 순간 커버 탭 — "내가 치던 걸 저 녀석이 치고, 나는 다음 걸 배운다". 도전자 B 예고에서 절초를 보고 파해 초식을 장착 → 대련 → 등급 상승.
- **실수 경험**: 오입력은 벌이 없다(셰이크만). 잘못 좁혀진 초식도 외운 초식이라 완주하면 유효한 응수. 미인식 스와이프는 `?` 로 "읽히지 않았다"가 보인다.
- **검증 로그 (M1 셀프·봇·지인 2~4인 → 동일 스키마로 M3 이후 라이브)**: `first_fire_t` ≤ 60s (kill a) / `first_transmit_t` ≤ 150s / `cycle_done_t` ≤ 300s 완주율 ≥ 70% (kill d < 50%) / 힌트 소멸 후 `fire/(fire+timeout)` ≥ 60% (kill b < 50%) / 세션당 `cover` ≥ 10 / 100% 초식 `oneTap` 비율 ≥ 70% / `ignore_rate`·`swipe_reject_rate` 초반 5수 (표면 명확도) / `tail_ms = fire − narrow` 분포 (꼬리 등급 근거) / 설문 "전수 순간이 기분 좋았다" ≥ 4/5 (kill c 과반 ≤ 3).

## 예상되는 문제점과 해결 방안

1. **첫 키 전에 "뭘 눌러야 하는지" 멈춘다** — 후보 3개가 다 보여도 지금 맞는 초식을 모른다(첫 5초 이탈).
   → 해결: 후보 아이콘에 첫 키 문양 상시 내장 + 예고 색에 대해 *우세* 속성인 후보 테두리 펄스. 속성 색은 판정 설계 §5 가 "항상 노출"로 정한 정보라 스포일러 아님(하수 60% 설계 의도). 파해(100%)는 강조하지 않음. **통합 spec 이라 판정부 ② 가 같은 빌드에 있어** 강조가 "정답 따라 치기"로 굳지 않는다 — 우세를 따라가도 파해·연환·선기를 노리는 선택이 실제 판정으로 차이 난다(§7 예시 우세 11.7 vs 완파 16.2 + 빈틈). 강조 on/off 는 접근성 파라미터.

2. **오입력·미인식이 "게임이 안 눌린다"로 읽힌다** — 데스크톱 무진동·모바일 무음.
   → 해결: 입력 시도 3종 전부 피드백(수락 = 버퍼 진행 / 무시 = 셰이크 200ms + 회색 화살표 튕김 + 둔탁음 / 미인식 = 궤적 끝 `?`). 같은 창 안 무시 3회 → 리셋 버튼 하이라이트. 로그 `ignore`·`swipe_reject` 분리로 두 원인을 따로 측정.

3. **잘못 든 갈래로 좁혀졌는데 모른 채 완주** — 접두어 공유에서 2번째 키 실수는 후보 0 이 아니라 *다른 초식 1개*.
   → 해결: (i) 후보 1 도달 시 아이콘 중앙 확대 + 이름 표시로 "이걸로 간다" 즉시 인지 (ii) **실전 장착 조건 = 숙련 ≥ 30%** 라 그 초식의 잔여 시퀀스도 유저가 외운 상태 → 그대로 완주가 유효한 응수(상성 판정) (iii) 되돌리기는 리셋 버튼 — 3길이 2.6s 창에서 1키 후 리셋 + 3키 재입력 ≈ 0.3 + 0.9s 로 성립, 4·5길이는 사실상 포기 버튼이라는 점을 설계상 인정(그래서 (ii) 가 1차 해결책).

4. **응수 창이 4·5길이에서 하수에게 부족 → 리듬게임처럼 빡빡하다**(§13 시장 리스크 — 리듬게임 오독).
   → 해결: `T = 2.6 + 0.4×(len−3)` 로 v0 실측 창(같은 길이 = 같은 창) 승계 + 접근성 ×1.3. 2.0s 는 D3 튜닝 하한 목표로만. 선기는 `T` 정규화라 긴 초식 불리 없음.

5. **제자 실패 → 커버가 늦어 "자동화가 나를 더 바쁘게 한다"** — v0 실측 4키 커버 3건 미커버(1650ms 에 4키).
   → 해결: `autoDelayRatio` 0.35(커버 여유 65% ≈ 4키 3.0s 창에서 1.95s) + 커버 알림을 제자 패널 적색 + 진동 + 후보 리스트가 제자 초식 1개로 즉시 좁혀진 상태로 뜸(사부는 꼬리만 치면 됨). 커버 성공마다 제자 성공률 상승이 보여 "커버 = 제자를 키우는 손맛"으로 읽히게 `+Δ` 를 제자 패널에 숫자로.

6. **전수 시연 3회가 지루한 반복으로 읽힌다** — 이미 100% 인 초식을 또 친다.
   → 해결: 시연 = 수련 모드 UI 재사용이되 **제자가 따라 치는 연출**(사부 입력 → 제자 궤적 0.3s 딜레이 미러) + 3회 카운터 + 마지막 회차 전수 스팅어. 3 은 `BALANCE.transmitReps` 로 노출, 봇 실측 첫 전수 ≤ 150s 를 넘기면 2 로.

7. **사이클 후 재화가 남아 의미 없는 숫자가 된다** — v0 실측 3분 673원 잉여, 수련 시뮬 1시간 +3,063원.
   → 해결: 프로토타입은 재화 싱크를 새로 만들지 않는다(M2 #3) — 대신 `simEfficiency` 0.3 → 0.1 + 비급 2·3·4식 가격을 잉여 흡수 수준(v0 60/150 → 4식 300)으로 올려 "다음 식을 사려면 대련 2~3회" 압력을 만든다. 재화 표시는 다음 비급 가격 대비 진행 바로.

8. **6단 판정 결과가 한 수 안에 읽히지 않는다** — 연출 0.5s 에 등급·피해·빈틈이 동시에 뜸.
   → 해결: 등급은 **색 + 한 글자**(완파 금·우세 청·상쇄 회·열세 주황·역파 적·피격 적) 를 판정 즉시 중앙에, 피해 숫자는 HP 바 감소 애니메이션으로, 빈틈은 다음 수 예고 자리에 「빈틈!」 배너 — 세 정보가 시간·위치 다르게 분리. 접근성: 색 + 글자 + 형태 중복.

  - 근거: v0 봇 실적(격파 19 · 실패 12)은 정답 1개 치기만 하던 규칙 — 창 전량이 실행. v2 는 § 목적 (a) 대로 같은 창 안에 "예고 색 대조 → 우세 판단 → 첫 키 선택"이 앞에 붙음. 목적이 창 부하를 늘리는데 창 값은 그대로, 작성자가 "이미 빠듯"하다 한 값을 기준선으로 삼음. 접근성 ×1.3 은 옵션이라 기본 판정 경로 여유 0. 5길이 3.4s 를 봇 v2 스펙으로 계산하면 판단 시간 사실상 0 → kill (b)·(d) 가 창 튜닝 미스로 오판정될 위험.

  - 권장 처리: debate 안건

  - 토의 유형: 해결책 합리성 검증
  - 권장 처리: debate 안건
